# mystia-steward-companion

**mystia-steward-companion** 是面向《东方夜雀食堂》的 BepInEx IL2CPP Mod。它读取游戏当前运行时数据，并通过独立桌面伴随窗口提供普客、稀客和夜间经营推荐。

项目由游戏内 Mod 读取运行时数据，并通过本地回环 API 提供给桌面伴随窗口展示和操作。

## 功能概览

### 实时数据与推荐

- 实时读取已解锁料理、酒水、食材、库存、流行标签、明星店状态和当前经营场景。
- 普客页按当前地区推荐料理与酒水。
- 稀客页按候选稀客和点单 tag 推荐料理、加料与酒水，可在设置页调整推荐排序规则和同基础料理展示数量。
- 经营中页自动检测当前稀客和普客订单，并用 `推荐` / `自动化` / `诊断` 视图分开展示订单推荐、自动化状态和排查信息；普客订单会显示原订单、实际料理/酒水方案、厨具、配方、加料和标签。
- 经营中订单可按点单顺序或稀客分组排列；偏好命中但不满足点单的候选会直接进入同一推荐列表，并以喜好备选标识区分。
- 支持收藏稀客常用料理方案和酒水；也可在 `自定义推荐料理` 页为指定稀客配置固定料理、加料、全部点单或指定点单 tag、推荐置顶和排序。

### 任务与稀客邀请

- 任务页可读取当前进度中可接取、进行中或可完成的交互任务，默认显示可接取和可完成任务。
- 任务状态支持多选筛选，并尽量显示未接取 NPC 所在场景；任务 ID 和读取来源默认隐藏，可用 `显示额外信息` 辅助排查。
- 任务页会列出日间场景中的稀客邀请候选，可在当前场景和全部场景之间切换；全部场景会保留当前场景已读取到的候选，并可按羁绊等级或名称搜索筛选。
- 可邀请项支持单独邀请或一次邀请全部，不满足羁绊或已邀请的项会显示原因并禁用按钮；当前已邀请稀客会单独汇总显示。

### 经营辅助与自动化

- 支持稀客订单专注模式，可调节料理/酒水显示数量并切换精简模式，减少滚动切换。
- 设置页提供实验性自动化总开关和自动化参数；开启后可在经营中页的 `自动化` 视图分别配置稀客订单和普客订单的处理阶段。
- `自动化` 视图会显示真实参与本轮调度的厨具预约和订单日志标识；特殊经营中因规则拦截的普客会单独显示为未占用厨具，不计入预约容量。每笔订单的执行步骤默认折叠在对应条目的自动化详情中。稀客自动化会锁定本次选择的料理/酒水，避免轮询刷新后中途换菜。
- 多个 Windows 或 Android 伴随窗口可以同时查看数据，但同一时间只有一个窗口能取得自动化控制权并执行自动化动作。
- 稀客和普客的酒水、出锅料理都会直接提交到目标顾客桌面；订单满足后才触发评价。
- 若厨具或伙伴效果让出锅结果变成非目标料理，或目标订单连续不可达，自动化会将该成品放入保温箱，并在下一轮重新尝试目标料理。
- 自动开始料理时会固定尝试完成原生 QTE 奖励结算。

### 运行时修改

- 修改页可按名称或库存排序材料和酒水，并用快捷按钮调整当前运行时库存数量。
- 支持把当前存档可编辑材料或酒水批量设为 99。

### 伴随窗口体验

- 独立伴随窗口可移动、缩放、置顶，并会记住上次的位置和大小，下次启动时自动恢复。
- `F8`/`RS Click` 可在游戏和伴随窗口之间切换，`F10` 可开启或关闭鼠标穿透锁定，游戏关闭后窗口会自动退出。
- 独立伴随窗口支持手柄导航，可用摇杆/十字键移动、确认、返回、切页、滚动和收藏推荐项。
- 可在可信局域网内让另一台 Windows 或 Android 设备运行伴随窗口，连接运行游戏和 Mod 的主设备；Release 会提供可直接运行的独立 Windows x64 伴随窗口 EXE，并可附带按 ABI 拆分的 Android APK。
- 本地 API 断开时窗口会保留最近一次只读数据用于查看，重连期间只做轻量健康检查，并停止自动化、置顶目标发布等会写入游戏运行时的后台动作。
- 设置页可分别调整背景透明度和文字透明度，并可配置置顶状态、主题、焦点切换行为、连接与 LAN 访问、推荐权重、预算处理、缺失厨具过滤、任务料理/收藏料理/收藏酒水置顶、带库存显示与排序的排除材料/酒水、同基础料理展示数量、稀客专注模式默认精简、实验性游戏界面置顶和目标厨具高亮。

### 日志、帮助与排查

- 概览页和经营中页 `诊断` 视图会显示关键快照耗时，用于排查运行时读取或自动化导致的卡顿。
- 日志页提供总日志开关、总日志目录和一键诊断包导出；总日志统一记录 BepInEx/Unity 事件、自动化、前端候选跳过原因、经营诊断和运行时数据诊断。
- 经营中页的订单和自动化状态会显示 `日志 R-0001` / `日志 N-0001` 这类标识，可在总日志中按 `trace=R-0001` 或 `trace=N-0001` 查找同一笔订单的自动化记录。
- 帮助页使用目录树展示功能用法、常见问题、卡顿排查和诊断信息收集步骤。
- Mod 默认关闭下一次启动的 BepInEx 控制台日志窗口，并在当前 Windows 会话尝试隐藏控制台；排查运行期问题时优先使用日志页的总日志和诊断包。

### 当前限制

- 经营中页会提示已识别的特殊经营挑战；调试模式下的 `诊断` 视图会展示已确认可捕获的目标 Tag、目标营业额、进度或符卡计数。特殊经营激活时，游戏界面置顶和目标厨具高亮只发布当前排序中第一笔可执行计划目标，避免展示候选与自动化目标分叉。怪诞料理大赛会按阶段选择高评价或命中当前目标 Tag 的执行料理，第二阶段和三阶段分身会硬性要求先满足原订单料理/酒水、触发最高评价并命中当前目标 Tag，小石本体会按场上揭示的正面/厌恶/酒水 Tag 选择执行目标，破防前送齐后触发常规评价，破防期会先满足原订单料理/酒水要求，再结合剩余目标分和预算规划投食总分，并交由 Boss 原生流程评价；此阶段自动化目标与推荐列表首项使用同一规划结果。若开锅后阶段或目标 Tag 变化，成品会进入保温箱并在下一轮重新推荐。幽幽子第二阶段会避开实际厌恶 Tag 并优先保证安全评价；第三阶段会避开实际厌恶 Tag，剧情版和重修版 P3 boss 普客都保持原订单料理/酒水匹配，优先选择按等级合计预测橙评/粉评的可推进目标；若原订单只能预测绿评，会以清理模式调用原生评价清理当前普客订单但不承诺推进进度；低于绿评、含厌恶 Tag、目标不一致或回调链不完整时会停止自动送达和评价。剧情版通过手动 `onEvaluate` 链路评价，重修版确认原生进度回调后走游戏 `EvaluateOrder()`，喜好命中只作为同评价内排序参考，纯营业额目标仅展示。

