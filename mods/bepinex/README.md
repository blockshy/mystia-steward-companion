# mystia-steward-companion Mod 使用说明

本文档面向普通用户，说明安装、更新、页面使用、跨设备连接和故障排查。开发、构建和运行时实现细节见 [开发说明](README.dev.md)。

Mod 会在读取存档后刷新游戏数据。标题画面、主菜单或加载过程中出现“运行时数据不可用”通常是正常现象，进入可操作场景后会自动恢复。

## 安装 BepInEx

1. 打开游戏根目录。Steam 中可通过“管理 -> 浏览本地文件”进入；目录中应能看到游戏 `.exe` 和 `GameAssembly.dll`。
2. 打开 [BepInEx Bleeding Edge 下载页](https://builds.bepinex.dev/projects/bepinex_be)。
3. 下载当前已验证的 Windows 64 位 Unity IL2CPP 包：

```text
BepInEx-Unity.IL2CPP-win-x64-6.0.0-be.783+c58c42d.zip
```

当前不建议使用 #784 或之后的构建，不同 Bleeding Edge 构建之间可能存在兼容性差异。

Linux 主机通过 Steam/Proton 运行游戏时也应使用上述 Windows x64 包，不要安装 Linux 版 BepInEx，并在 Steam 启动选项中设置：

```text
WINEDLLOVERRIDES="winhttp=n,b" %command%
```

4. 将压缩包内容解压到游戏根目录，确认存在：

```text
BepInEx/
doorstop_config.ini
winhttp.dll
```

5. 启动游戏一次，等待 BepInEx 生成 IL2CPP interop 文件。首次启动可能较慢。
6. 关闭游戏，确认 `BepInEx/config`、`BepInEx/core`、`BepInEx/interop` 和 `BepInEx/plugins` 已生成。

如果这些目录没有出现，通常是 BepInEx 包类型、解压位置或启动方式不正确。

## 安装 Mod

从 [GitHub Releases](https://github.com/blockshy/mystia-steward-companion/releases) 下载：

```text
mystia-steward-companion-bepinex.zip
```

把压缩包中的 `mystia-steward-companion/` 整个目录放到 `BepInEx/plugins/`：

```text
游戏根目录/
  BepInEx/
    plugins/
      mystia-steward-companion/
        MystiaStewardCompanion.BepInEx.dll
        companion/
          mystia-steward-companion.exe
```

启动游戏后，`BepInEx/LogOutput.log` 中应出现 Mod 已加载和本地 API 已启动的信息。伴随窗口通常会自动打开，也可以按 `F8` 唤起。

需要在另一台设备显示伴随窗口时，只在运行游戏的电脑安装完整 Mod：

- 另一台 Windows 设备下载 `mystia-steward-companion-companion-windows-x64.exe`，直接双击运行。
- Android 设备优先安装 `mystia-steward-companion-android-arm64-v8a.apk`；较旧的 32 位设备使用 `armeabi-v7a` 版本。

另一台设备仍需通过运行游戏电脑上的 Mod 读取数据，不能单独使用。

## 更新 Mod

支持自动更新的版本会在发现正式新版后显示提示。进入 `设置 -> 更新` 可以检查、下载并打开独立安装程序；Mod 不会在游戏运行中自动替换文件，也不会自动关闭游戏。

首次安装、旧版本不支持自动更新，或自动更新不可用时，按以下方式手动更新：

1. 关闭游戏和伴随窗口；如果窗口仍在托盘中，请从托盘菜单退出。
2. 可选备份：

```text
BepInEx/config/com.tyukki.mystia-steward-companion.cfg
BepInEx/config/MystiaStewardCompanion/
```

3. 删除旧的 `BepInEx/plugins/mystia-steward-companion/`。
4. 将新版压缩包中的同名目录放回 `BepInEx/plugins/`。
5. 重新启动游戏，确认伴随窗口或日志中的版本号已经更新。

注意：

- 不要解压成两层 `mystia-steward-companion/mystia-steward-companion/`。
- 只替换插件目录不会删除收藏、自定义料理、设备配置或主配置。
- 更新提示只针对运行游戏电脑上的 Mod；另一台 Windows 设备和 Android 设备上的伴随客户端需要单独更新。
- 默认只检查正式版本；预览版仅供主动开启 `Updates.IncludePrerelease` 的测试者使用。

从 `v1.3.0` 起不再提供 `favorites.json` 到 `custom-recipes.json` 的旧自定义料理迁移。仍在 `v1.1.x` 或更早版本且使用过旧手动自定义料理的用户，应先安装并启动一次 `v1.2.0`，确认 `custom-recipes.json` 已生成并备份两个 JSON 文件，再升级到 `v1.3.0`。已经正常运行过 `v1.2.x` 的用户无需额外操作。

## 快速开始

1. 启动游戏并读取存档。
2. 等待伴随窗口自动打开；没有显示时按 `F8`。
3. 在 `概览 -> 状态` 确认连接和推荐数据已经就绪。
4. 在 `推荐料理` 查看经营前建议，在夜间经营中使用 `经营中` 页面。
5. 自动化、任务列表和稀客邀请默认关闭；游戏界面辅助可在实验性功能页按需配置。
6. 第一次启用会改变游戏状态的功能前，建议备份存档并阅读窗口内的 `设置 -> 帮助`。

## 页面功能

### 概览

- `状态`：连接、插件版本和运行时数据状态。
- `库存`：低库存材料和酒水。
- `操作`：常用快捷键和窗口操作。
- 开启调试信息后会显示额外的来源和性能字段。

### 推荐料理

| 子页面 | 用途 |
| --- | --- |
| `普客` | 按当前场景查看普通客人的料理和酒水建议。 |
| `稀客` | 选择场景、稀客和点单 Tag，查看料理、加料与酒水组合。 |
| `自定义推荐料理` | 为指定稀客和点单条件维护固定料理方案及优先级。 |
| `收藏管理` | 搜索、查看和取消料理或酒水收藏。 |

自定义方案、收藏和推荐置顶只改变候选顺序，仍会检查解锁、库存、材料、预算、排除项和可用厨具。收藏管理不会修改自定义料理内容。

### 经营中

经营中页显示当前场景、订单、推荐方案和自动化状态：

- `推荐`：分别查看稀客和普客订单的当前主方案与其他候选。
- `自动化`：查看每笔订单的执行阶段、暂停原因，并按需重试、重置或确认人工处理。
- `诊断`：仅在开启调试信息后显示，用于排查订单、厨具和特殊经营状态。

每笔订单都有 `R-xxxx` 或 `N-xxxx` 日志标识。反馈单笔订单问题时，请同时提供该标识。

### 扩展功能

| 子页面 | 用途与注意事项 |
| --- | --- |
| `任务列表` | 只读显示可接取和进行中的任务。模块默认关闭，开启后才读取和刷新列表。 |
| `稀客邀请` | 查看今晚已邀请名单，并按日间场景邀请符合条件的稀客。模块默认关闭。 |
| `修改` | 修改当前材料或酒水数量。修改后需要在游戏内保存才会写入存档。 |

任务列表不会替玩家接取、完成或领取任务。稀客邀请只写入今晚邀请名单，客人是否实际出现仍由游戏流程决定。使用修改功能前建议备份存档，避免在经营消耗过程中同时改库存。

### 设置

| 分栏 | 主要内容 |
| --- | --- |
| `窗口` | 主题、透明度、字体、置顶、鼠标穿透、焦点切换、手柄导航和调试信息。 |
| `连接` | 本机与局域网连接、Token、设备列表、主设备和配置同步。 |
| `推荐` | 排序权重、预算、排除项、收藏/任务置顶和展示数量。 |
| `实验性功能` | 自动化与游戏界面辅助。页面顶部会提示相关风险。 |
| `更新` | 自动检查状态、手动检查、下载和安装入口。 |
| `帮助` | 按功能查阅更详细的操作、限制与排障说明。 |

### 日志

日志页仅在 `设置 -> 窗口 -> 显示调试信息` 开启后出现，可控制总日志、打开日志目录、导出诊断包，以及在游戏电脑本机显示或隐藏 BepInEx 控制台。

## 推荐规则

推荐会先排除当前无法安全执行的方案，例如未解锁、材料不足、超出所选预算策略、命中排除项或缺少可用厨具。其余候选按以下优先级处理：

1. 当前活动任务的目标料理。
2. 已启用并置顶的自定义推荐料理。
3. 收藏的料理和酒水。
4. `设置 -> 推荐` 中启用的普通排序权重。

推荐页面、经营中首项、自动化和游戏界面辅助共用同一笔订单的主方案。修改排序、预算或排除设置后，系统会按当前游戏状态重新计算。

常用设置：

- `同基础料理显示`：控制同一道基础料理最多展示多少个不同加料方案。
- `经营中订单排序`：按点单顺序或稀客分组显示，也会影响自动化处理顺序。
- `预算处理`：阻止、提示或忽略超预算组合。
- `排除材料 / 排除酒水`：临时保留指定库存，不让它参与推荐。
- `收藏料理 / 收藏酒水置顶`：只改变已通过安全条件的候选顺序。

特殊经营会根据已确认的游戏规则调整推荐和自动化。目前包括怪诞料理大赛、幽幽子挑战与重修、寻找瑞灵踪迹、月都试炼 1/2/3、血池地狱等；无法确认订单身份或挑战状态时会暂停相关执行，不会套用普通经营规则。用户可在经营中页查看原因，机制与研究记录见 [特殊经营说明](../../docs/special-business-scenes-notes.md)。

## 自动化

自动化默认关闭，属于会改变游戏状态的实验性功能。建议先在可回退存档中测试。

启用步骤：

1. 进入 `设置 -> 实验性功能`。
2. 开启自动化总控。
3. 分别开启稀客或普客处理。
4. 按需开启送达酒水、开始料理、送达料理和完成订单。
5. 在 `经营中 -> 自动化` 观察每笔订单的实时状态。

主要行为：

- 稀客与普客可以独立启用，并分别设置并发数量。
- 直接送达酒水或料理依赖同组的 `自动完成订单`；只想自动开锅时，可以只开启 `自动开始料理`。
- 稀客可以限制为只使用收藏料理或收藏酒水。
- 厨具暂忙、游戏暂停或对象暂不可用会进入等待；材料不足、没有可执行推荐或达到重试上限时会显示明确原因。
- 配置开关或主设备发生变化时，已开始的料理不会被强行撤销。系统会在下一安全步骤暂停，并在有效配置恢复后继续。
- 如果玩家取走或替换了自动化正在跟踪的成品，系统会停止占用该厨具并按现场状态处理，不会猜测库存或重复执行不确定动作。
- 出现 `需人工确认` 时，应先检查厨具、订单、库存和保温箱，再点击 `确认已处理`；反复切换开关不会自动清除此状态。
- 教学经营会暂时暂停自动化，离开后按原设置恢复。

自动化参数和每种暂停原因的详细说明可在伴随窗口 `设置 -> 帮助 -> 自动化` 中查看。

## 游戏界面辅助

游戏界面辅助位于 `设置 -> 实验性功能`，稀客和普客可以分别配置颜色与开关：

- 在游戏的料理、食材和酒水列表中置顶并高亮当前主方案。
- 在制作页显示目标料理的加料选项。
- 高亮目标厨具、桌位、左下订单卡片和投掷送达按钮。

这些功能只处理当前已确认的订单目标；订单完成、目标变化、功能关闭或经营结束后会更新或清除提示。加料料理选项会实际改变选中配方并扣除材料，因此风险高于纯高亮功能。

如果开关变化或订单刷新后高亮没有更新，先保持页面和现场不变，开启调试信息与总日志并导出诊断包。如果加料选项无响应、材料退扣结果不明确或页面提示状态不确定，请停止继续点击，关闭制作页后核对库存，再保存完整日志和截图。系统不会猜测退款或重放无法确认的库存操作。

## 独立伴随窗口

Windows 伴随窗口支持移动、缩放、置顶、透明显示、鼠标穿透和系统托盘。关闭按钮默认隐藏到托盘，可通过以下方式重新打开：

- 在游戏内按 `F8` 或 `RS Click`。
- 使用托盘菜单的显示命令。
- 再次双击伴随窗口 EXE。

如果游戏使用独占全屏，置顶和焦点切换可能受系统限制，建议改用无边框窗口化或窗口化。

开启鼠标穿透后，鼠标点击会落到下方窗口；按 `F10`、`F8`、`RS Click` 或使用托盘菜单可以恢复操作。

### 同机连接

由游戏自动启动或通过 `F8` 唤起时，伴随窗口会接收本地 API Token。直接双击 EXE 可能停留在未授权状态；保持游戏运行并按 `F8`，已有窗口会重新接收连接信息。

修改连接地址或 Token 后需要点击 `连接`。连接失败时会逐步放慢重试，也可以点击 `停止` 暂停自动重连。

### 另一台设备连接（Windows / Android）

以下以 A 设备运行游戏和 Mod，B 设备只运行伴随窗口为例。两台设备必须位于同一个可信局域网。

A 设备：

1. 安装 BepInEx #783 和完整 Mod，启动游戏并读取存档。
2. 在本机伴随窗口进入 `设置 -> 连接`。
3. 开启 `允许局域网设备连接`。
4. 复制与 B 设备同一网段的推荐 LAN 地址和 Token。
5. 如果连接超时，在 Windows 防火墙中允许游戏 EXE 接收所用端口的入站连接，默认端口为 `32145`。

B 设备：

1. 启动独立 Windows 伴随窗口或 Android 客户端。
2. 填写 A 设备的完整 LAN 地址，例如 `http://192.168.1.20:32145`。
3. 填写 A 设备提供的 Token，然后点击 `连接`。
4. 在 `设置 -> 连接` 查看设备列表、在线状态和生效配置版本。

连接注意事项：

- B 设备不能使用 `127.0.0.1`，该地址只代表 B 设备自身。
- 不要填写 `0.0.0.0`，也不要把本地 API 暴露到公网。
- 浏览器访问 `http://A设备地址:32145/health` 可检查网络和防火墙是否可达，但不能证明 Token 和完整功能可用。
- VPN、虚拟网卡或多个 LAN 地址并存时，应选择与 B 设备同网段的 A 设备地址。
- Android 版不支持桌面托盘、窗口置顶、鼠标穿透和游戏关闭后自动退出。

多设备配置规则：

- 第一个完成注册的窗口会成为初始主设备，之后不会因离线自动转移。
- 推荐、自动化和游戏界面辅助只使用主设备保存的共享配置；非主设备可以查看，但相关设置为只读。
- `同步配置` 会用主设备的整套共享配置覆盖目标非主设备，不会合并两边的值。
- 希望另一台设备接管时，建议先同步，等待显示“与主设备一致”，再点击 `设为主设备`。
- 窗口主题、字体、连接地址、调试显示等本地界面偏好仍按设备单独保存。
- 收藏和自定义料理保存在游戏电脑上，所有已连接设备共用。

A 设备本机窗口会随游戏关闭而退出；远程 Windows 或 Android 客户端会保留界面并进入重连状态。断线期间不会继续执行自动化或发布新的游戏界面辅助目标。

## 配置与数据位置

主配置：

```text
BepInEx/config/com.tyukki.mystia-steward-companion.cfg
```

用户数据：

```text
BepInEx/config/MystiaStewardCompanion/favorites.json
BepInEx/config/MystiaStewardCompanion/custom-recipes.json
BepInEx/config/MystiaStewardCompanion/companion-devices.json
BepInEx/config/MystiaStewardCompanion/aggregate-mod.log
```

常用配置项：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `ToggleKey` | `F8` | 游戏与伴随窗口切换热键。 |
| `ControllerToggleKey` | `JoystickButton9` | 手柄切换热键，常见为 `RS Click`。 |
| `Companion.AutoLaunch` | `true` | 是否自动启动本机伴随窗口。 |
| `LocalApi.AllowLanConnections` | `false` | 是否允许可信局域网设备连接。 |
| `LocalApi.LanHost` | `auto` | 自动选择或手动指定私网监听地址。 |
| `LocalApi.Port` | `32145` | 本地 API 端口。 |
| `Diagnostics.EnableAggregateModLog` | `false` | 是否启用总日志。 |
| `Diagnostics.ShowBepInExConsoleOnStartup` | `false` | 是否在启动时显示 BepInEx 控制台。 |

Windows 伴随窗口的位置和大小保存在 `%APPDATA%\com.tyukki.mystia-steward-companion`，界面偏好保存在 `%LOCALAPPDATA%\com.tyukki.mystia-steward-companion`。

## 日志与诊断

普通使用无需开启总日志。需要反馈识别、推荐、自动化或游戏界面辅助问题时：

1. 开启 `设置 -> 窗口 -> 显示调试信息`。
2. 进入 `日志` 页并开启总日志。
3. 完整复现一次问题。
4. 导出诊断包，记录相关订单的 `R-xxxx` 或 `N-xxxx` 标识。
5. 同时提供操作顺序、截图或短视频；分享前检查日志中的本机路径和游戏状态信息。

总日志默认写入：

```text
BepInEx/config/MystiaStewardCompanion/aggregate-mod.log
```

单个文件达到 10 MB 后会轮转，默认最多保留 30 个文件。排查结束后建议关闭总日志，避免长期占用磁盘。

`BepInEx/LogOutput.log`、`output_log.txt` 和 `Player.log` 是共享日志，不受 Mod 总日志轮转规则管理。如果共享日志异常变大，应先退出游戏，保留需要的末尾内容后再手动处理。

日志页的控制台按钮只允许在游戏电脑本机使用。Mod 新建的控制台会禁用窗口关闭命令，避免误关游戏；需要关闭显示时请使用日志页按钮。

## 故障排查

### `F8` 无法打开独立窗口

确认 `mystia-steward-companion.exe` 位于：

```text
BepInEx/plugins/mystia-steward-companion/companion/
```

如果放在其他位置，请在 `Companion.ExecutablePath` 中填写绝对路径。

### 伴随窗口鼠标点不到

通常是开启了鼠标穿透。按 `F10`，或通过托盘菜单关闭鼠标穿透。

### 一直显示运行时数据不可用

先确认已经读取存档并进入可操作场景。仍未恢复时，开启调试信息和总日志，导出诊断包。

### 经营中没有订单或推荐

确认客人已经入座并完成点单，再查看经营中页是否显示读取或安全阻止原因。无法定位时提供诊断包和订单日志标识。

### 自动化卡住或反复等待

在 `经营中 -> 自动化` 查看暂停原因，再到诊断视图检查厨具和订单状态。厨具暂忙、材料不足、没有可执行推荐、收藏限定、特殊经营安全门禁或等待玩家处理都可能暂停。普通失败可使用 `重试` 或 `重置`；出现 `需人工确认` 时先核对游戏现场，再确认已处理。

### 夜间经营订单较多时卡顿

临时降低稀客或普客自动化并发，或关闭暂时不需要的订单组和游戏界面辅助。仍有问题时开启总日志复现，并记录订单数量、已启用功能和当时的性能字段。

### 启动时出现控制台或早期中文乱码

BepInEx 可能在 Mod 加载前创建控制台并输出日志，Mod 无法阻止或修复这部分早期输出。可以在本机日志页隐藏控制台；若不希望进程启动时创建窗口，需要调整 BepInEx 自身的全局控制台配置。

### 重置设置

先关闭游戏和伴随窗口，再按需要删除：

- 插件配置：`BepInEx/config/com.tyukki.mystia-steward-companion.cfg`
- 收藏、自定义料理、设备记录和总日志：`BepInEx/config/MystiaStewardCompanion/`
- 仅重建设备列表：只删除其中的 `companion-devices.json`
- Windows 窗口位置和大小：`%APPDATA%\com.tyukki.mystia-steward-companion`
- Windows 界面偏好：`%LOCALAPPDATA%\com.tyukki.mystia-steward-companion`

删除配置或用户数据无法自动恢复，操作前请先备份需要保留的文件。
