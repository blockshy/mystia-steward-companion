# mystia-steward-companion Mod 使用说明

本客户端使用 Flutter，面向《东方夜雀食堂》Mod 用户提供密集列表、推荐详情、扩展模块与可选自动化。游戏电脑运行完整 Mod，Windows 或 Android 伴随客户端负责显示和操作。开发资料见[开发说明](README.dev.md)。

标题画面、主菜单和加载过程中，游戏数据可能尚未读取完整。进入可操作场景后会刷新；未知数据不会显示为零库存或空结果。

## 安装 BepInEx

1. Steam“管理 → 浏览本地文件”打开游戏根目录，确认存在游戏 EXE 与 GameAssembly.dll。
2. 从 [BepInEx Bleeding Edge](https://builds.bepinex.dev/projects/bepinex_be) 下载本项目已验证的 `BepInEx-Unity.IL2CPP-win-x64-6.0.0-be.783+c58c42d.zip`。
3. 解压到游戏根目录，确认存在 BepInEx/、doorstop_config.ini 与 winhttp.dll。
4. 首次启动游戏等待生成 interop，再关闭游戏；确认 BepInEx/config、core、interop、plugins 已生成。

不要把其他 Bleeding Edge 构建当作已经验证。Linux/Proton 运行 Windows 游戏时仍使用 Windows x64 包，并设置 Steam 启动选项 `WINEDLLOVERRIDES="winhttp=n,b" %command%`；本轮 Flutter 产品没有进行 Proton 验证。

## 安装 Mod

从[项目发布页](https://github.com/blockshy/mystia-steward-companion/releases)取得与本说明对应的完整包，或使用本地已验证构建。新客户端必须使用同一套 Mod 与客户端，不能只复制 EXE 或主 DLL。

```text
BepInEx/plugins/mystia-steward-companion/
  MystiaStewardCompanion.BepInEx.dll
  MystiaStewardCompanion.Contracts.dll
  MystiaStewardCompanion.Business.dll
  mystia-steward-companion-updater.exe
  package-manifest.json
  companion/
    mystia-steward-companion.exe
    flutter_windows.dll
    其他依赖 DLL
    data/
```

保留压缩包中完整 companion 目录及全部资源。另一台 Windows 电脑使用完整的 `mystia-steward-companion-companion-windows-x64.zip`，解压后运行；Android 使用对应的 arm64-v8a 或 armeabi-v7a APK。独立客户端仍需连接游戏电脑。

此源码分支的完成不表示已经发布 GitHub Release；实际可下载版本以发布页为准。

## 更新 Mod

新包采用完整目录替换。进入“设置 → 更新”可以检查、下载整包并请求退出游戏后安装。更新程序确认目标进程退出，核验全部文件，失败时恢复备份；不会在运行的游戏中替换程序集。

从旧客户端首次迁移时使用完整包安装入口，不能用旧单 EXE 更新方式：

1. 关闭游戏、托盘中的客户端及更新程序。
2. 备份原插件目录以及 BepInEx/config/MystiaStewardCompanion/ 和主配置。
3. 将原插件目录移到 BepInEx/plugins 之外保留，再放入新完整目录；不要把旧 companion 文件混进新目录。
4. 原插件内如有额外用户文件，单独保留并确认用途；不要盲目删除。
5. 新客户端以新设备身份注册，按下述迁移流程同步配置。

收藏、自定义料理、设备注册表和 Mod 设置仍位于 BepInEx/config，不由插件目录替换清理。另一台 Windows 或 Android 设备需分别更新。

## 快速开始

1. 启动游戏并读取存档，等待伴随窗口出现；未出现时按 F8。
2. “总览”确认经营场景和今日供给；设备角色与连接详情在“设置 → 连接与设备”查看。
3. 经营前使用“推荐”；夜间使用“经营”浏览订单、主方案与阻断原因。
4. 在“扩展”的自动化、游戏界面辅助页签按需开启共享总开关并配置分项。
5. 任务列表、稀客邀请和库存修改的页签常驻，在各自页签内打开本机开关；三个开关默认关闭且各设备独立保存。

## 页面功能

| 页面 | 内容 |
| --- | --- |
| 总览 | 经营状态、今日供给与食材/酒水合并低库存表 |
| 经营 | 稀客/普客、订单方案、自动化状态、专注与统计信息 |
| 推荐 | 普客、稀客、料理/酒水收藏、自定义配方、推荐偏好 |
| 扩展 | 任务列表、稀客邀请、库存修改、自动化、游戏界面辅助，各页签内部独立启停 |
| 数据 | 料理与酒水图鉴，按解锁状态筛选、搜索；资源管理 |
| 设置 | 连接与设备、外观、更新、诊断、帮助 |

### 窗口、列表与反馈

Windows 各窗口宽度均使用固定窄侧栏，设置入口位于侧栏底部；Android 使用底部六项导航，页内标签可横向滚动。底部状态栏显示连接、角色、客户端/Mod 版本与操作反馈，手机点击摘要可查看完整状态。宽屏采用列表/详情分区，窄窗口和手机点击行后查看详情，返回保留列表位置。页面刷新不会自动跳转。暖色与深色主题、字体缩放、减少动效可在外观设置调整。Windows 默认背景完全不透明；调低背景不透明度可透出后方窗口，输入框、下拉框、按钮及选中项的填充也受背景不透明度控制；文字、图标和边框由独立的内容不透明度控制。Android 不显示桌面透明度选项。

连接、角色、版本和最近一次操作反馈集中在底栏；页面读取、刷新与保存的详细提示可从标题右侧打开。设置始终使用顶部横向页签，Android 页签保持单行横向滚动。搜索与对应结果页签同排，宽屏列表与详情并排，窄屏进入详情后可返回原浏览位置。

输入、下拉与按钮随字号统一增长；只读标签保持紧凑。料理、酒水的“指标”行显示来源提供的标价、成本、利润、库存或覆盖情况；厨具、配方、加料、匹配各自成行。摘要余项以“+N”表示，详情显示完整标签与说明。标签用途由文字、图标和颜色共同区分，不仅依赖颜色。

## 连接与设备

“连接与设备”在连接成功后显示当前连接摘要、来源和本设备角色。启动参数提供的连接在本次进程中锁定，地址、Token和连接名称不可手工修改；断线或初始化失败时沿用原参数“重试连接”。其它连接可通过“修改连接”调整并取消，使用“保存并连接”重试；连接过程中禁止重复提交。设备列表中的“本设备”按设备身份标注，与“主设备”角色分开显示，不按名称或操作系统判断。

设备列表用“本设备”标记当前客户端；“主设备”表示共享配置和自动化的控制角色，两者独立。准备换主设备时，先在目标记录点击“同步主配置”，等待落盘确认，再选择“设为主设备”。同步完整覆盖目标设备的共享配置，不合并两边的值。只有主设备可点击同行的“忘记设备”删除其他离线查看设备；本设备、主设备和在线设备受到保护。

首个注册设备可成为初始主设备，已有主设备不会因离线自动让位。查看设备共享可见结果；相关业务设置只由主设备编辑。收藏和配方由游戏电脑统一保存，本机外观按设备保存。

已有手动连接的 Token 会在“修改连接”时回填，默认掩码，可主动显示；取消编辑不会断开当前连接。更换地址时，未手动编辑的旧 Token 会清空，请填写目标游戏电脑的凭据。Token 仍保存在系统安全存储，显隐不会取消认证与主设备权限。

## 另一台设备连接（Windows / Android）

游戏电脑 A 与客户端 B 位于同一个可信局域网：

1. 在 A 本机作为主设备进入“设置 → 连接与设备”，查看常驻的“局域网服务”。“刷新配置”重新读取服务状态和实际网卡，不会保存草稿。
2. 选择与 B 同网段的网卡，或选择“自动（全部网卡）”。自动模式监听全部符合条件的私有网卡；不支持手输任意绑定地址。
3. 按需设置 8–128 位非空白可见 ASCII 字符的 Token，开启局域网服务，点击“保存服务配置”。核对监听状态及实际连接地址。
4. 复制与 B 同网段的 LAN 地址，用“复制连接 Token”取得已保存凭据。B 填写如 `http://192.168.1.20:32145`、Token 和设备名，点击“保存并连接”。
5. 如需接管，先同步主配置并等待确认，再设为主设备。

修改 Token 需确认；保存成功后本机客户端沿用原设备身份接续新凭据，其他设备需修改连接中的 Token。修改监听或凭据失败时先检查当前状态，不通过反复保存猜测结果。启动参数锁定只限制当前连接表单，不阻止游戏电脑本机主设备管理局域网服务。

B 不能使用 127.0.0.1 或 0.0.0.0。多网卡/VPN 环境选择实际同网段地址；防火墙需要允许游戏 EXE 的指定端口。不要将 API 暴露到公网。

Android 没有桌面托盘、置顶、穿透及游戏退出联动。远程客户端不会因为游戏电脑断开而自动退出。

## 历史数据迁移

新客户端不会复用旧设备身份或 Token 数据库。旧主设备记录和共享配置留在游戏电脑；自动化按已保存的共享总开关运行：

1. 同机启动接收 Mod 凭据，或在“设置 → 连接与设备”填写地址、Token 和名称。
2. 有旧主设备时，先点击当前设备的“同步主配置”。
3. 等待同步落盘并确认完成，再将新设备设为主设备。
4. 核对共享自动化、推荐与高亮设置；自动化总开关若已开启，新主设备会在连接、配置确认和场景条件满足后恢复执行。
5. 旧设备记录可在确认迁移完成后显式忘记。

“历史偏好迁移”接受一次性导出的 JSON，格式为 `{"schemaVersion":1,"preferences":{"旧键名":"字符串值"}}`。它只读取白名单偏好，拒绝身份和秘密字段；原文件保留。窗口、主题、字号、不透明度、页面选择及任务列表/稀客邀请的旧模块开关映射到新客户端。此前已导入的历史记录会在新开关尚未设置时补齐，明确关闭的本机设置不会被覆盖。库存修改没有旧模块开关可迁移，默认关闭；其余已解析字段保留在迁移记录中，不恢复已移除的旧页面行为。不能直接把浏览器数据库文件当作该 JSON。

更早的自定义料理历史：使用过 v1.1.x 及之前旧手动自定义料理的用户，仍应先通过 v1.2.0 生成并备份 custom-recipes.json；新客户端不会重新启用旧存储 schema。

## 推荐、收藏与自定义配方

### 普客与稀客

推荐的普客、稀客页面在条件确定后自动查询；切换地点、客人或标签会更新结果，等待过程中显示加载提示，失败可重试。稀客首次进入会选择首个具有完整标签的客人，也可手动更换；料理和酒水需求来自该客人各自的标签列表。切换客人时保留仍可用的标签，其余恢复到新列表首项。

普客按地点查看料理或酒水覆盖；稀客按客人及其料理、酒水需求标签查询。结果搜索仅筛选当前料理或酒水名称。覆盖人数与命中标签总数是不同指标，不能互相替代；推荐用于准备时，也不表示当前已经出现对应订单。

### 推荐偏好

推荐结果由 C# 提供；经营料理与酒水来自同一主方案。收藏、自定义配方和评分权重均受解锁、库存、预算、排除项与厨具条件约束。推荐 → 推荐偏好集中管理预算、排除资源和评分。均衡、节约资源、利润、简单料理四个预设固定且有选中态；选择自定义后才能修改权重、参与开关和方向，已有手动调整的数值会迁入自定义保留。数值滑块位于设置条目右侧，拖动后自动应用；方向键可按一步精调。外观滑块在拖动中持续预览并自动保存。预算不足策略使用右侧下拉选择器；推荐地点、客人和需求标签使用相同风格的可搜索下拉框。

推荐 → 推荐偏好 → 排除资源采用动态标签：展开添加食材/酒水，搜索名称后选择；候选和已选标签均按明确编号显示图片，缺图保留通用图标，已选标签可直接移除。保存期间会暂时禁用操作，失败时保留原配置。

### 收藏

在稀客推荐结果中加入收藏，或在聚焦的推荐行按手柄 X。料理收藏保存客人、需求和追加食材，酒水收藏保存对应需求与酒水；在“推荐 → 收藏”按料理/酒水和名称/客人筛选，再选择记录移除。收藏保存在游戏电脑，不能绕过解锁、库存、预算、排除项与厨具约束；“仅收藏”自动化限制在扩展中配置。

### 自定义配方

“推荐 → 自定义配方”提供两种独立保存的模式。“料理模式”按料理分组，进入料理后添加稀客绑定；“稀客模式”按稀客分组，进入客人后添加料理。每条绑定都指定稀客和料理，可从该客人的需求标签中选择限定标签，或使用“全部点单标签”，再按需选择加料。新增和编辑使用同一对话框；组内可启用/停用、置顶、调整顺序或确认删除。

编辑对话框中的料理、稀客、追加食材候选及已选食材显示对应图片，基础配方和厨具也使用相同图标槽。图片只按明确编号与唯一配方关联，不以同名食材猜图；目录缺失的历史加料仍显示编号并可移除。

仅当前模式的已启用条目参与推荐，切换模式保留另一模式的全部配置；总开关关闭时两种模式均不参与计算，也不删除条目。已有合法旧版 custom-recipes.json 会自动迁入稀客模式，保留原绑定、标记与顺序；两种模式不会自动相互复制。切换模式、连接或共享配置在编辑期间变化时，需要重新打开编辑核对。自定义配置由游戏电脑保存，并由当前主设备管理。

模式通过带选中背景和单选标记的互斥控件切换，当前启用模式单独标明；总开关关闭时显示未启用，但保留当前选择。保存期间暂时禁用切换，同一模式不会重复提交。

## 经营、专注与统计

### 实时订单与方案

经营页的稀客、普客各有“订单方案”和“自动化状态”页签。订单列表按游戏中的桌号显示，稀客订单直接列出点单需求、同一主方案的料理和酒水、基础配方、加料、厨具及预算/限制；没有主方案时明确提示并显示具体阻断原因。普客列表区分原订单和实际方案，展示送达与评价状态。配方、材料、加料、厨具和酒水采用不同颜色与图标的标签，分组面板与列表选择有明确层次。

订单固定按首次观察到点单的时间先后显示，同一时间保持稳定顺序。自动化与游戏界面辅助独立遵守特殊场景的执行优先级；列表位置不代表执行资格。

新订单立即显示已知的客人、桌号、点单和送达状态，尚未返回的推荐字段显示等结构占位。同一订单刷新时保留仍有效的方案，参考与等待提示放在页头；场景、订单需求或连接变化后撤销不匹配内容。常见方案到达后尽量保持位置，长名称或多材料仍会自然增高。

订单方案列表、详情和专注的短进度放在订单标题右侧，已有料理、已有酒水等不会重复占据订单底部；自动化状态使用整行身份，阶段与进度各自分行。加载、刷新、连接和保存提示集中在页面标题右侧，点击可查看完整信息；错误优先显示，多个来源不会互相清空。需要人工确认的事项通过“待确认”入口查看和处理，仍需核对游戏现场并由有权限的设备确认。

订单方案、自动化状态和专注卡片的柔和底色统一沿用普客/稀客目标颜色，且随窗口背景不透明度变化。分色依据订单类别，与头像属于稀客还是普通客群分别判断；它不表示游戏正在高亮该订单，也不表示当前可以自动处理。游戏界面辅助关闭后，窗口仍保留两类底色。

### 专注

“经营 → 专注”将实际稀客和普客订单集中展示，制作信息仍来自当前同一主方案。在“专注显示 · 本机”可选择显示客人类型、点单需求、料理、基础配方、加料、厨具和酒水；桌号和客人身份始终保留。选项只保存本机显示偏好，不修改共享自动化、推荐规则或游戏界面辅助；断线不显示缓存方案，缺失方案与必要阻断继续提示。人工确认可直接使用待确认入口，重试与完整诊断回到对应订单页。关闭“显示窗口 UI”会收起导航、页头和底栏；“专注显示”设置始终可访问，保存失败仍显示紧凑错误入口。退出专注后保留原客人类型、筛选草稿和订单浏览位置。

“稀客优先”默认关闭，专注页默认合并普客与稀客的点单时间顺序；开启后先显示稀客组，两组内部仍保持原顺序。此选项仅影响本机专注展示，不恢复旧共享排序规则，也不改变自动化优先级。

### 统计信息

“经营 → 统计信息”在专注右侧，集中展示当前订单数量、自动化配置与状态、暂停原因、待确认事项、当前厨具与自动化拟分配。待确认事项提供直接入口，核对现场后按原流程处理。订单数随现场即时更新，不等待推荐完成；拟分配代表本轮计划使用锅位，不等于实际占用。总览不再重复统计与连接详情，食材和酒水低库存合并为四列表。

当前厨具按现场读取结果显示，非经营场景、尚未读取和读取失败分别提示；多功能厨具不能跨类型累加。自动化配置、状态与暂停原因分开显示，只有实际存在事项时提供“查看待确认事项”入口。高级原始读取诊断可展开查看。

## 扩展模块

扩展的所有模块页签常驻，不需要先经过管理页。任务列表、稀客邀请和库存修改在各自页签中显示本机启用开关，查看设备也能调整；需要修改游戏时仍须是主设备。模块开启且当前可见才读取对应信息，关闭或离开页面会停止附加读取。关闭后保留当前页签并显示关闭说明，库存选择清除；操作进行中不能切换开关，确认期间模块已关闭或页面已离开时不会提交旧操作。自动化和游戏界面辅助使用共享总开关，离开其页签不等于停用。

### 任务列表

任务列表只读展示追踪任务和当前已确认可接取任务；外层直接显示标题、状态、角色/来源字段及逐条条件。不会替玩家接取、完成或领取任务。关闭任务列表不影响推荐偏好中的任务料理优先；可接取任务只覆盖已确认的触发来源，不是所有游戏任务的静态全集。

### 稀客邀请

在稳定日间场景选择当前地图或全部地图，再按羁绊等级筛选。客人资料卡直接显示头像、姓名、地点、羁绊、原因与邀请按钮，无需进入详情。未知羁绊、场景变化或不可邀请原因不会被忽略。

邀请的实时地点来自当前地图确切的NPC登记，两种地图范围都可展示已确认位置；未登记或读取不可用会分别说明，不能据此断言客人在“其他地图”。全部地图模式不会因位置未确认而改变原有邀请资格。邀请说明与其它字段按首行文字基线对齐，长原因在内容列内换行。正常任务 Ready、邀请人数摘要不占用独立提示行；必要等待放在页头，场景限制和读取错误继续保留。

邀请的羁绊等级与“邀请筛选范围”按钮保持同排；窄屏可横向滚动等级，右侧操作按钮仍可见。批量邀请仍需确认当前地图范围和所选羁绊等级，不因布局变化扩大操作范围。

名称搜索只缩小可见列表，批量“邀请筛选范围”仍以地图范围和勾选的羁绊等级为准。邀请成功表示加入今晚名单，不保证立刻出现；提交结果未确认时先核对，不重复邀请。

### 库存修改

“库存修改”只允许勾选和全选数量明确的有限库存；无限库存、未知数量及不唯一编号只读。完整读取并确认的零库存仍可补充，未加载或读取不完整时不猜测为零。提交后重新读取游戏库存并展示结果；批量部分失败会保留实际计数和原因，失败不会显示前一次成功提示，也不会自动重发。

每条物品可直接点击“−10”或“+10”，只修改当前物品，不连带批量已选项；越过0–9999范围时禁用，提交期间不可重复点击。复选框与表头全选对齐，相对整个条目垂直居中；批量目标数量仍使用原确认流程。

点击“名称”或“库存”表头切换排序，再次点击同一字段反转方向，未知库存始终后置。表头复选框全选当前筛选中可修改的项目，再次点击清除当前结果；筛选外的已选项保留并明确计数。切换食材/酒水分类或关闭模块会清选。

批量修改填写 0–9999 的目标数量并点击“设置已选条目”，在确认框核对全部条目和数量；单项 −10/+10 不改变批量勾选。游戏中的数量或可编辑性在确认期间改变时会取消旧操作。修改当前库存后仍需正常保存游戏才写入存档。

## 自动化

普客开锅前核对实际配方的材料份数。缺料时显示具体原因，不占用厨具或挡住其他可行订单；补充材料后自动恢复。经营刷新中的参考和等待提示位于页头，仍匹配当前订单的方案会保留显示；保留显示不表示当前可以执行，操作前仍会检查最新状态。

在“扩展 → 自动化”配置总开关，并分别设置稀客/普客处理范围、烹饪、取送酒水、料理交付和完成订单。总开关保存在共享配置中，下次启动或重新连接沿用；新设备首次注册的默认配置关闭自动化。普客、稀客步骤中各有自己的并发数；“同一步骤失败上限（共享）”在开启出错暂停时按同一步骤失败次数决定暂停，首次失败计入；成功或切换步骤清零。“重新安排次数上限（共享）”约束返回制作/重新选择方案的累计恢复，达到上限暂停，0表示首次需要恢复时即暂停，不会返还材料。两项修改任一区均影响普客和稀客。

- 只有主设备连接正常、配置同步完成，且订单与经营状态检查通过时才执行。
- 断线、切主、配置待确认或场景不满足时暂停新的动作；不会由另一个设备自动接管。
- 普通暂停订单可在自动化状态中重试；标明需要人工确认的事项必须先检查现场，再确认已处理。
- 不确定动作不会因反复点击而自动重放。料理已开始不意味着可以安全强行撤销。
- Windows 隐藏到托盘时仍保持自动化连接；作为主设备的 Android 进入后台后会暂停自动化，回到前台并恢复连接后，按已保存配置和现场条件继续。

特殊经营规则由 Mod 统一处理。无法确认订单身份或挑战状态时，页面展示原因并停止相关动作。机制说明见[特殊经营说明](../../docs/special-business-scenes-notes.md)。

“经营 → 稀客/普客 → 自动化状态”分开显示客人身份、阶段、送达进度、处理目标和异常。已锁定的料理与酒水使用真实目标编号展示图片及材料、厨具，不改用最新推荐；普通标准订单尚无锁定目标时，仅在唯一确认原点料理的配方后显示该配方并标明来源。特殊替换目标不明时不拿原订单冒充执行目标；已请求送达仍须等待现场确认。

## 游戏界面辅助

位于“扩展 → 游戏界面辅助”，有独立共享总开关；关闭会停止辅助效果并保留分项与颜色。稀客与普客分别配置列表置顶、配方变体、厨具/座位/订单高亮及颜色。当前颜色和选择按钮在条目右侧；点击预设色即可应用，也可打开二维颜色面板调整颜色与色相，确认后应用，取消保留原值，无需输入颜色代码。全新配置默认关闭；已有配置迁移时按旧分项是否开启保留原有效果。服务端决定当前目标，前端不会上传自行计算的执行方案。

此总开关只控制游戏内辅助效果，不隐藏伴随窗口按普客/稀客分类显示的订单底色。窗口使用相同两类颜色便于辨认全部订单，而游戏高亮仍只作用于 Mod 确认的当前目标。

配方变体涉及真实材料变化；遇到状态不确定时停止重复点击，核对游戏现场并导出诊断。开启高亮或置顶不会跳过自动化所需的订单、库存、厨具和场景检查。

## 数据与图像资源

数据页的料理与酒水图鉴默认筛选已解锁，可切换未解锁或全部，并按名称/编号搜索。料理按已学会配方判断，酒水按游戏图鉴收录判断，与当前库存无关。未读取或状态不完整时显示未知，可切换全部浏览已有目录；图鉴只读，基础资料不代表当前可制作的订单方案。

数据详情在顶部一次显示完整标签，下方保留说明、负面标签和编号，不重复同一组标签。图鉴中的基础资料、收藏中的保存条件和经营中的匹配结论用途不同，不互相代替。

料理、酒水、食材、厨具、人物与普通客群通过精确编号显示游戏图片，名称、用途颜色与操作方式保留；图片随字号缩放，缺图或关联不明确时回退原图标。人物采用图鉴像素头像；普通客群采用该客群固定的代表形象，不改变游戏随机皮肤。普通订单的头像按游戏确切客人类型核对：复制的稀客显示对应稀客头像，无法确认时用通用图标，不按名称或数字范围猜测，也不改变该订单的处理方式。

图片由 Mod 首次加载时初始化。缓存核验、等待游戏目录、实际提取及失败均在同一个独立初始化界面显示对应状态，完成后自动进入工作台；核验不表示重新提取图片，失败保留错误及重试入口。初始化、核验与重读期间暂停业务操作和自动化。

`user-data/game-media` 中的旧缓存若没有启动凭据，需要进入存档完成一次完整确认；已有 PNG 通过校验后原样复用并补建凭据。之后游戏版本、已启用 DLC 与资源未变化且缓存完整时，可在主菜单完成校验并复用，无需先读档。每次启动仍检查资源身份、缓存清单和图片文件。安装包不包含游戏图片；Android 经已认证连接读取同一份已验证资源。

数据 → 资源管理默认浏览全部分类，也可切换单类并按名称或编号搜索；游戏更新后先重启游戏，再由主设备按需重新读取。搜索只筛选已有资源清单，不为匹配内容额外提取图片。日常订单与页面刷新只使用缓存，不重新提取纹理。

## 内置帮助

“设置 → 帮助”提供分类目录和全文搜索，覆盖安装与连接、推荐与收藏、经营、自动化、扩展、库存、诊断和更新。分类默认全收起，搜索时临时展开命中分类，清除搜索恢复手动展开状态。宽屏目录与正文并排，窄屏可进入文章后返回目录。正文分别列出操作、说明和注意事项；无需连接游戏即可阅读。

常见 Mod 配置包括 Companion.AutoLaunch、LocalApi.AllowLanConnections、LocalApi.LanHost、LocalApi.Port 和 Diagnostics.EnableAggregateModLog。修改前关闭相关进程并保留备份。

## 日志与诊断

1. 在游戏电脑本机作为主设备进入“设置 → 诊断”，按需开启聚合 Mod 日志。
2. 复现并记录时间、场景、操作和订单 R-xxxx / N-xxxx 标识。
3. 使用“导出诊断包”，分享前检查本机路径和游戏状态信息；按需打开日志目录保留相关分片。
4. 排查后可关闭聚合日志；需要重新读取日志设置和包列表时点击“刷新诊断”。

默认单段 10 MiB、保留 30 段；保留数量可设置为1–30。BepInEx LogOutput.log 和 Unity Player.log 不由该轮转管理。本机 Windows 可控制 BepInEx 控制台显隐；使用页面按钮隐藏，不关闭 Mod 创建的控制台窗口。

“最近操作 · 本次运行”保留最近 20 条实际动作、时间及成功/失败/结果待确认状态，不记录后台轮询、Token 或原始请求正文。客户端重启后不会恢复这份操作列表；需要跨次排查时使用日志。

“诊断包”列出本项目已导出的包名、大小和时间，可“刷新列表”并由主设备确认删除指定包。读取失败不会冒充空列表，也不能继续删除旧记录；文件在确认期间发生变化时需重新读取。删除只影响指定诊断 ZIP，不清理原始日志、配置或存档。

日志配置、导出、打开目录和控制台操作在游戏电脑本机进行；已认证设备可以查看诊断包列表，主设备也可远程删除已确认的诊断包。控制台开关反映当前显隐状态，成功操作后保存启动偏好，不另列重复的“启动时显示控制台”字段。

## 故障排查

- F8 无法打开：确认 companion 完整目录存在，EXE 与 Flutter DLL/data 未拆开；检查日志。
- 鼠标点不到：按 F10 关闭穿透，或用托盘恢复。
- 游戏数据尚未就绪：确认已读取存档并进入可操作场景；自动化暂停时查看经营 → 统计信息中的自动化状态和“暂停原因”。
- 没有推荐：查看订单需求、库存、预算、排除项、收藏限制和阻断原因。
- 自动化暂停：先查看自动化详情中的当前阶段、下一步和异常原因；实际送达与已发送请求分开显示。普通暂停可重试；需要人工确认的事项必须先核对现场再确认。
- 连接失败：先查看窗口底栏的具体错误，完整内容也可在“设置 → 诊断”查看。初始化失败会保留失败阶段，切页不会将其清除；在“设置 → 连接与设备”可重新初始化并连接：启动参数连接点击“重试连接”，其它来源点击“保存并连接”，不需要删除原设备身份。同机启动由 Mod 提供凭据；手机再检查地址、Token、LAN 监听错误与防火墙。重连不会更改已保存的自动化开关，也不会重放此前未知结果的游戏写操作。
- 重置数据：先备份，关闭进程后按用途处理配置或设备记录。删除凭据会产生新设备身份，不能借此直接接管主设备的自动化。

开发验证入口与证据要求见[验证指南](../../docs/validation-guide.md)。离线预览、组件测试和构建结果不能替代目标平台及真实经营场景的专项验证。
