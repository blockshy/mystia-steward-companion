# mystia-steward-companion Mod 使用说明

本文档面向普通用户，说明 BepInEx 安装、Mod 安装/更新、伴随窗口使用、常用设置和故障排查。开发、构建和本地 API 说明见 [README.dev.md](README.dev.md)。

Mod 会在读取存档后刷新游戏当前运行时数据。游戏仍在标题、主菜单或加载页面时，伴随窗口可能显示“运行时数据不可用”；进入可操作场景后会自动刷新。

## 安装 BepInEx

1. 找到游戏根目录。Steam 可通过“管理 -> 浏览本地文件”打开，目录中应能看到游戏 `.exe` 和 `GameAssembly.dll`。
2. 打开 BepInEx Bleeding Edge 下载页：<https://builds.bepinex.dev/projects/bepinex_be>。
3. 下载与系统和游戏架构匹配的 Unity IL2CPP 包。当前项目在 Windows 64 位下建议使用已经验证的 #783 构建：

```text
BepInEx-Unity.IL2CPP-win-x64-6.0.0-be.783+c58c42d.zip
```

   BepInEx Bleeding Edge 是开发构建，不同构建之间可能有兼容性差异。本项目当前不建议使用 #784 或之后的构建；如果后续确认新版可用，再按新版说明更新。

4. 将压缩包内容解压到游戏根目录。解压后应出现：

```text
BepInEx/
doorstop_config.ini
winhttp.dll
```

5. 启动游戏一次，等待 BepInEx 生成目录和 IL2CPP interop 程序集。首次启动可能较慢。
6. 关闭游戏，确认以下目录存在：

```text
BepInEx/config/
BepInEx/core/
BepInEx/interop/
BepInEx/plugins/
```

如果没有生成这些目录，通常是下载了非 IL2CPP 包、解压位置错误，或游戏没有成功启动过一次。

## 安装 Mod

发布包文件名通常为：

```text
mystia-steward-companion-bepinex.zip
```

将压缩包中的 `mystia-steward-companion/` 整个目录放入游戏目录：

```text
游戏根目录/
  BepInEx/
    plugins/
      mystia-steward-companion/
        MystiaStewardCompanion.BepInEx.dll
        companion/
          mystia-steward-companion.exe
```

安装后启动游戏。`BepInEx/LogOutput.log` 中应出现类似日志：

```text
mystia-steward-companion 1.x.x loaded. Press F8 to open or focus the companion window.
Local API loopback listener is available at http://127.0.0.1:32145
```

如果只想在另一台设备上运行伴随窗口，不需要把完整 Mod 发布包安装到 B 设备。Windows 设备可下载 Release 中的独立伴随窗口 EXE，下载后直接双击运行，不需要解压：

```text
mystia-steward-companion-companion-windows-x64.exe
```

Android 设备可下载 Release 中对应 CPU 架构的 APK。普通手机和平板优先选择 `arm64-v8a`，只有较旧设备再选择 `armeabi-v7a`：

```text
mystia-steward-companion-android-arm64-v8a.apk
mystia-steward-companion-android-armeabi-v7a.apk
```

这些独立伴随窗口只用于 B 设备连接 A 设备上的游戏；A 设备仍必须按上面的方式安装 BepInEx 和 Mod。

## 更新 Mod

支持自动更新的版本会在 Mod 启动后按配置检查新版本，并在工作台显示非模态提示；点击 `查看更新` 会直接进入设置页的更新分栏，也可以选择 24 小时后再提醒。检查失败会按 15 分钟、30 分钟、1 小时、2 小时、4 小时到最高 6 小时退避重试，成功后恢复配置的检查间隔。自动检查不会自动下载、安装或关闭游戏。

发现新版本后，可以在更新分栏中手动检查、下载和打开安装程序；更新包会先保存到配置目录，校验版本、长度和 SHA256 后，实际替换由独立更新程序在弹窗中提示关闭游戏并显示进度。下载和安装不会并行；更新窗口仍在运行时不会覆盖暂存目录或重复启动。暂存版本不高于当前版本时不会允许安装，避免旧下载导致降级。首次安装或从不支持自动更新的旧版本升级时，仍按下面的手动流程处理。

默认只检查正式版本。预览版仅用于自动更新测试，普通用户不需要开启；测试者如需参与预览版更新链路，可以在配置文件中设置 `Updates.IncludePrerelease = true`。

手动更新时只需要替换插件目录，通常不需要删除配置和收藏数据。

1. 关闭游戏。
2. 确认伴随窗口也已退出；如果仍在托盘中，右键托盘图标并选择退出。
3. 可选备份以下用户数据：

```text
BepInEx/config/com.tyukki.mystia-steward-companion.cfg
BepInEx/config/MystiaStewardCompanion/
```

4. 删除旧插件目录：

```text
BepInEx/plugins/mystia-steward-companion/
```

5. 解压新版 `mystia-steward-companion-bepinex.zip`，把新的 `mystia-steward-companion/` 放回：

```text
BepInEx/plugins/
```

6. 启动游戏，在伴随窗口顶部或 `BepInEx/LogOutput.log` 中确认版本号已变为新版。

注意事项：

- 不要把新包解压成 `BepInEx/plugins/mystia-steward-companion/mystia-steward-companion/` 这种嵌套目录。
- 收藏配方保存在 `BepInEx/config/MystiaStewardCompanion/favorites.json`，自定义推荐料理保存在 `BepInEx/config/MystiaStewardCompanion/custom-recipes.json`，只替换插件目录不会覆盖它们。
- 自动更新使用 GitHub Release 中的 `update-manifest.json` 校验更新包 SHA256；该清单不包含本机打包路径。
- 预览版 Release 不会被默认更新检查命中；只有手动开启 `Updates.IncludePrerelease` 的测试者会收到。
- 普通窗口位置、大小、最大化状态等由桌面程序保存到 `%APPDATA%\com.tyukki.mystia-steward-companion`；背景透明度、文字透明度、字体大小等界面偏好保存在 `%LOCALAPPDATA%\com.tyukki.mystia-steward-companion`。若需要完全重置，请先退出伴随窗口，再删除这两个目录，下次启动会重新生成。
- 更新提示和操作针对所连接游戏电脑上的 Mod 主包；其他设备单独安装的 Windows 伴随窗口和 Android APK 不会通过该提示自行更新。
- Windows 可能缓存旧 exe 图标。若更新后图标看起来没变，通常是系统图标缓存问题，不影响 Mod 功能。

`v1.2.x` 保留一次性自定义料理迁移：Local API 启动时会把 `favorites.json` 中旧 `source=manual` 料理原子写入 `custom-recipes.json`，确认写入成功后再移除旧收藏条目。升级过程中断可在下次启动安全重试，不需要先安装中间版本。自 `v1.2.0` 起不再读取旧 GUID 配置 `com.tyukki.mystia-steward.cfg`；已正常启动过正式 `v1.1.x` 的安装不受影响。

## 快速开始

1. 启动游戏并读取存档。
2. Mod 会自动启动独立伴随窗口。若没有显示，按 `F8`。
3. 在 `概览` 页确认连接状态和推荐数据已就绪。
4. 日常查看推荐：
   - 进入 `普客` 页查看当前经营场景的普通客人推荐。
   - 进入 `稀客` 页按场景、稀客和点单 Tag 查看推荐。
   - 进入夜间经营后，在 `经营中` 页查看实时稀客/普客订单。
   - 进入 `任务` 页查看可接取和已追踪任务，或切换到 `稀客邀请` 分栏管理今晚邀请名单。
5. 排查问题时，再到 `设置` 页开启 `显示调试信息`，此时会出现日志页和更多诊断字段。

## 快捷键与手柄

| 操作 | 说明 |
| --- | --- |
| `F8` | 在游戏与独立伴随窗口之间切换焦点；窗口隐藏或关闭到托盘时会重新显示。 |
| `F10` | 开启或关闭伴随窗口鼠标穿透锁定；穿透时鼠标点击会落到下方游戏或其他窗口。 |
| `RS Click` | 手柄默认焦点切换键，作用与 `F8` 类似。 |
| 左摇杆 / 十字键 | 伴随窗口获得焦点且手柄导航开启后移动焦点；滑杆、数字输入和分段选项按控件自身语义调整。 |
| `A` | 确认当前按钮或控件。 |
| 下拉框上的 `A` | 展开下拉选项；展开后再用左摇杆或十字键移动选项。 |
| `B` | 先关闭已展开的下拉框或确认弹窗；没有弹层时返回上一级或退出稀客订单专注模式。 |
| `LB` / `RB` | 切换页面。 |
| `LT` / `RT` | 滚动当前获得焦点的局部滚动区域；没有局部区域时滚动当前页面。 |
| 推荐行上的 `A` / `X` | 收藏或取消收藏当前料理/酒水。 |
| 推荐行上的 `Y` | 进入稀客订单专注模式；专注模式内切换精简模式。 |

Windows 下可直接使用 WebView2 识别为 `standard` 映射的 Xbox 手柄，蓝牙连接不要求启用 Steam Input；对未知的非标准映射不会猜测按钮编号。连接、重连、切回窗口或重新开启手柄导航后，请先松开摇杆和按键，输入回到中立位置后才会重新响应。关闭“手柄导航”只停用窗口内导航，`F8` / `RS Click` 的窗口切换仍然有效。

## 页面功能

### 概览

概览页通过页签拆分状态、库存和快捷操作：

- `状态`：显示连接状态、插件版本、运行时数据和推荐数据状态。
- `库存`：显示低库存材料和酒水，便于决定是否补货。
- `操作`：显示常用快捷键和窗口操作入口。
- 开启 `设置 -> 窗口 -> 显示调试信息` 后，会额外显示 API 状态、运行时来源和快照耗时。

### 普客

普客页按当前经营场景统计普通客人偏好，并给出料理和酒水推荐。推荐只作为经营准备参考，不会自动修改库存。

### 稀客

稀客页用于提前查看稀客推荐：

- 按经营场景筛选可选稀客。
- 选择稀客后，再选择点单料理 Tag 和酒水 Tag。
- 推荐列表会显示料理、分数、成本、厨具、基础配方、加料和酒水。
- 同一道基础料理有多个加料方案时，可在设置页控制每道基础料理最多显示几个当前排序最优的变体。
- 可在推荐行收藏料理或酒水；需要固定推荐某些未自动排到前列的料理时，使用 `自定义推荐料理` 页集中维护。

### 自定义推荐料理

自定义推荐料理用于给稀客配置固定料理方案：

- 可选择稀客、指定点单料理 Tag，或选择 `全部点单` 让该料理对该稀客所有料理 Tag 生效。
- 可选择基础料理和额外加料；游戏最多允许 5 个材料，页面会按基础配方原始材料数量和加料数量限制。
- 页面总开关控制全部自定义配方是否参与推荐、自动化和游戏界面置顶；关闭不会改写单条启用、置顶和排序状态，重新开启后恢复原配置。
- 管理列表可按稀客或基础料理分组，并可对全部配方、当前分组或单条配方执行启用、停用、推荐置顶和取消置顶。
- 推荐优先级只在同一稀客内调整；按基础料理查看时不显示上移、下移，避免跨稀客排序产生无效或误导结果。
- 稀客页和经营中页的料理推荐区可查看当前生效的自定义配方；实际推荐仍会继续检查解锁、库存、排除材料、预算阻止和缺失厨具过滤。

### 经营中

经营中页顶部显示经营场景、推荐数据、自动化状态、特殊经营摘要、已摆放厨具和目标厨具。下方通过 `推荐` / `自动化` / `诊断` 视图分区：`推荐` 视图用于日常查看订单与推荐，`自动化` 视图集中阶段开关和订单执行详情，`诊断` 视图仅在开启 `显示调试信息` 后出现，用于查看原始当前稀客、当前稀客点单、预计厨具占用、特殊经营订单、扫描来源和性能字段。

`推荐 -> 稀客` 页签：

- 显示当前点单推荐，严格满足点单的料理和酒水优先。
- 偏好命中但不满足点单的料理或酒水会进入同一推荐列表，并显示“偏好备选”标识。
- 可进入稀客订单专注模式，只保留当前点单推荐；专注模式支持精简显示和推荐数量设置。
- 未完成的稀客订单会通过运行时订单对象和反射回退持续校验，避免未上菜时提前从列表消失。
- 若运行时缓存偶发留下过时稀客订单，可在诊断视图的原始订单行右侧点击删除按钮清理该笔缓存。

`推荐 -> 普客` 页签：

- 显示当前普通客人订单、桌位、订单来源和日志标识。
- 每笔普客订单会同时显示原订单和当前执行方案；普通经营显示基础配方，特殊经营会显示实际料理/酒水方案、厨具、基础配方、加料、最终标签和规则原因。

`自动化` 视图：

- 开启自动化后，可按独立阶段处理稀客和普客订单。
- 显示订单日志标识、执行步骤、暂停原因和重试/重置入口。
- 单笔订单的执行明细默认折叠在对应订单下方，排查时可手动展开。

`诊断` 视图：

- 仅在开启 `显示调试信息` 后显示。
- 显示当前稀客、桌位、携带金钱、当前稀客点单与删除入口。
- 显示按当前推荐、自动化状态和完整厨具快照推导的预计厨具占用；它用于诊断，不是后端锁表。
- 显示特殊经营订单汇总、扫描状态、普客来源、性能耗时和界面辅助状态。

### 任务

任务页包含 `任务列表` 和 `稀客邀请` 两个分栏。

`任务列表` 分栏：

- 合并显示当前可接取任务与已接取且仍活动的任务，并使用 `全部`、`可接取`、`可完成`、`进行中`、`待确认` 页签切换分类；页签显示各类数量，`全部` 仍按状态、任务标题和内部标识稳定排序。每项任务会显示任务定义关联的角色和该角色静态配置的相关场景；相关场景表示可能出现地点，不表示角色当前实时位置。
- 首版可接取列表只覆盖已经过实机接取前后闭环验证的 `KizunaCheckPoint` 羁绊检查点事件，且任务必须来自 `postMissionsAfterPerformance`。普通角色对话等其他触发类型暂不发布为可接取任务。
- 每次读取可接取列表都会在 Unity 主线程重新读取当前日和永久调度事件，并严格核对任务前置节点、是否已活动、循环属性、完成历史，以及任务、日间场景和稀客映射代际；读取失败会显示明确状态，技术原因写入日志和诊断包，不把不确定结果显示成空列表。
- 可接取列表是纯只读展示。Mod 不调用游戏的事件触发、任务接取、完成、奖励或移除入口，也不会让尚未接取任务参与任务料理置顶、自动化、游戏界面置顶、列表高亮或厨具高亮。
- 每个读档任务只在任务系统初始化完成后执行一次原生条件状态刷新并立即校验；新接取任务在创建完成后确认初始状态，只有游戏原流程尚未刷新时才补做一次原生刷新。后续只被动接收游戏自身的任务刷新，不轮询任务状态，也不调用任务完成、奖励或移除入口。
- 首次进入、重新连接或任务读取代际变化时自动刷新，也可手动刷新。读取链不完整时显示明确状态，技术原因写入日志和诊断包，不把不确定结果显示成普通空列表。

`稀客邀请` 分栏显示日间场景中的候选：

- 支持当前场景或全部场景候选；日间运行态就绪后首次进入、切换范围、换图、日间场景重新初始化或重连都会自动读取，也可点击刷新强制重读，再按羁绊等级和名称搜索筛选。游戏暂时无法提供日间运行态时，页面会按 0.5、1、2、4 秒有限重试，之后显示具体原因并等待手动刷新或场景状态变化，不会把读取失败显示成空列表。列表读取只做精确查键，不刷新 NPC 或生成羁绊状态。
- 可邀请项支持单独邀请或一次邀请全部；已邀请、羁绊不足、当前场景下当前不可见或缺少成功邀请条件的候选会保留显示但禁用按钮。
- 当前已邀请稀客会在邀请区内单独汇总显示，便于确认今晚名单。
- 单独邀请和邀请全部会携带候选所属的日间场景代际和地图；请求进入游戏主线程后若场景已变化，Mod 会拒绝旧请求并提示刷新，不会把旧候选写入新场景。
- 邀请成功只写入游戏今晚邀请名单，不会直接刷出稀客，后续仍由游戏经营流程决定。

### 修改

修改页用于修改当前运行时库存：

- 材料和酒水列表可按名称或库存排序；单项材料或酒水支持 `-10`、`+10`、`99` 快捷修改。
- 支持 `材料全 99` 和 `酒水全 99` 批量修改当前可编辑库存。
- 游戏原生数量为 `-1` 的材料或酒水显示为无限，不参与普通单项或批量库存修改。
- 修改后需要在游戏内保存，才会持久化到存档。
- 建议先备份存档；经营中修改可能与实时消耗同时发生。

### 设置

设置页通过页签管理窗口、连接、推荐、自动化和更新：

- `窗口`：背景透明度、文字透明度、`90%` 至 `130%` 字体大小、焦点切换行为、切换冷却时间、始终置顶、鼠标穿透、主题、手柄导航、显示调试信息。

### 日志

日志页仅在 `设置 -> 窗口 -> 显示调试信息` 开启后显示：

- 可开启/关闭总日志。
- 可打开总日志目录。
- 可导出诊断包。
- 可在游戏电脑本机显示或隐藏当前进程的 BepInEx 控制台；显隐成功后会立即保存为下次启动偏好，默认关闭，局域网设备不能远程操作。

- 经营中页订单和自动化状态中的 `日志 R-0001` / `日志 N-0001` 对应总日志里的 `trace=R-0001` / `trace=N-0001`，排查单笔订单时优先按这个标识搜索。
- 最终没有可执行推荐方案时，订单提示和总日志会记录首个候选清零阶段、阶段计数、缺失材料/厨具及预算证据；同一经营会话中的相同状态有界去重，诊断不会改变候选或自动化目标。

- 总日志开启时删除或移走当前 `aggregate-mod.log` 后，下一条日志会自动重建原路径；无新日志事件时不会为了生成空文件而轮询磁盘。

## 推荐与排序规则

### 运行时数据

Mod 会尽量使用游戏当前运行时数据读取稀客、普客、料理、酒水、库存和场景信息。进入游戏并读取存档后，`普客`、`稀客` 和 `修改` 页面即可使用；夜间经营准备阶段和经营中场景会继续刷新库存、解锁和订单信息。

### 厨具过滤

进入夜间经营后，Mod 会读取当前场景完整的物理厨具字典，并将快照区分为完整和不可用。Mod 会先读取特殊事件锁定坐标：命中的条目只保留安全的字典坐标和实体身份计数，不再读取可能已被游戏销毁的控制器状态、类型或显示对象。其余控制器仍严格校验字典坐标、控制器坐标、原生实体身份、空位/已摆放与可开状态。空位和锁定条目都不计入推荐、自动化或高亮容量；任一其他条目失败时整轮不可用，不用部分厨具继续动作。存在锁定条目时，只有仍开放的控制器能够证明对应厨具类型可用，缺少开放证据的类型会暂时退出推荐，恢复后自动重新计算。

### 同基础料理展示数量

`同基础料理显示` 默认只展示每道基础料理当前排序最靠前的 1 个加料变体。调高该数值后，稀客页和经营中页会保留更多同基础料理的不同加料方案。每笔订单会先从完整候选中确定一组主执行方案，再把这组方案的料理和酒水放到页面首项；该设置只限制其余展示变体，不会把主执行方案挤出页面。

### 经营中订单排序

经营中订单排序默认使用 `点单顺序`。切换为 `稀客分组` 后，同一稀客的多笔订单会放在一起，稀客组之间仍按该稀客最早订单出现时间排列。

该设置会影响：

- 经营中列表。
- 稀客订单专注模式。
- 游戏界面置顶目标。
- 自动化处理的当前订单顺序。

### 推荐排序

推荐会优先满足当前点单的料理 Tag 和酒水 Tag；不满足点单但命中稀客喜好的方案会直接进入同一推荐列表，并以 `偏好备选` 标识说明不满足点单。经营中页和稀客订单专注模式会按当前显示数量截取统一列表，不再单独维护一套喜好备选区域。

推荐先应用解锁、库存、材料、厨具、预算阻止、排除项和自动化收藏限定等硬过滤，再依次应用任务料理置顶、自定义推荐置顶、收藏料理/酒水置顶，最后使用 `推荐权重` 中的启用项与权重决定普通顺序。默认均衡预设会综合稀客偏好、厌恶风险、加料数量、食材压力、预计利润、酒水库存和当前厨具可做等因素。

可在 `设置 -> 推荐 -> 推荐权重` 中选择预设、启用或关闭排序项，并调整权重。排序会先决定每笔订单的主执行方案，再影响 `稀客`、`经营中`、稀客订单专注模式和自动化开始时锁定的目标。

经营订单触发重新计算时，需求未变化的当前订单会继续显示上一轮推荐，新订单只在自己的位置显示“推荐计算中”；订单送达、结束，或连接、自动化会话、经营代际和特殊经营语义发生变化时，旧显示立即失效。该连续展示结果仅用于页面，自动化、游戏界面置顶、列表高亮、厨具高亮和桌位高亮仍只消费当前 Worker 代际的正式结果。

`任务料理置顶` 默认开启。普通经营中，如果游戏原生任务查询被动确认某笔唯一活动稀客订单需要提交指定料理，Mod 会把精确匹配该 `foodId + recipeId` 的候选提升为带有 `任务目标` 标识的主执行方案。该任务料理可以跳过普通的料理点单 Tag 和料理厌恶判断，但仍必须通过料理解锁与库存、材料、厨具、预算、排除项和自动化收藏限定等全部硬门禁，配对酒水也必须满足当前点单。关闭该设置或遇到未接取任务、特殊经营、订单身份不唯一、任务或经营代际不一致时保持普通推荐顺序。该主方案统一供页面首项、自动化、游戏界面置顶、列表高亮、厨具高亮和桌位高亮消费；多笔订单并存时，游戏内全局辅助目标优先选择主方案为任务方案的订单，但真正写入游戏列表仍由 `游戏界面置顶推荐` 独立控制。

### 收藏置顶

`设置 -> 推荐 -> 推荐设置` 中可开启 `收藏料理置顶` 和 `收藏酒水置顶`。自定义推荐料理的单条 `推荐置顶` 在自定义页面内配置。置顶只在解锁、库存、材料、预算阻止、排除项和缺失厨具过滤等硬条件通过后生效；任务料理置顶优先于自定义置顶，自定义置顶优先于收藏料理，收藏酒水只影响酒水排序。

### 预算和排除项

经营中稀客订单会尽量读取稀客当前剩余资金。`预算处理` 可选择阻止超预算、仅提示或忽略预算；开启后推荐行会显示预估价格和预算提示。订单标记为免费订单时不受付款预算阻止，非免费订单仍按当前预算策略处理。

`排除材料` 会让料理推荐避开指定材料，基础配方和加料都会检查；`排除酒水` 会让酒水推荐跳过指定酒水。排除项下拉会显示当前库存，并可按名称或库存排序，适合临时保留材料、避免使用特定库存，或处理当前不想供应的酒水。

### 特殊经营挑战

特殊经营挑战会在经营中页显示挑战名称、已捕获的 HUD 目标和自动化风险提示。挑战名称直接读取游戏 `NightSceneDirector.ChallengeType` 枚举成员的固定中文 `InspectorName`；Mod 不维护名称映射，也不使用社区昵称。元数据不可读时，页面只显示当前挑战标识，详细原因记录在诊断视图中。

## 自动化（实验性）

自动化默认关闭。需要使用时，先到 `设置 -> 自动化` 开启 `启用自动化（实验性）`，再到 `经营中` 页的 `自动化` 视图分别配置稀客和普客阶段开关。稀客与普客自动化互相独立。

建议先在可回退存档中测试，再长期使用。

如果同时打开 A 设备本机 Windows 伴随窗口和 B 设备 Windows / Android 伴随窗口，多个窗口可以同时查看数据和调整普通偏好；自动化会由本地 API 分配短时控制权。同一时间只有取得控制权的窗口会执行稀客或普客自动化，其他窗口会显示为仅查看，避免两边重复开锅、送达或评价。

临时断线或控制权转移不会删除 Mod 已登记的料理任务；重新取得控制权的窗口会从快照继续接管。新控制者取得控制权、明确关闭自动化，或在料理开始后关闭对应订单组的料理送达/订单完成阶段时，会等待当前已开始的游戏命令到达完整执行边界，再作废其余旧命令并取消尚未进入不可逆步骤的料理任务；不会清空厨具、返还已扣材料、撤销已经开始的原生副作用或改动玩家成品。

### 自动化参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 稀客并发 | `2` | 同时跟踪和处理的稀客订单数量。 |
| 普客并发 | `3` | 同时处理的普客订单数量。 |
| 最大重试 | `3` 次 | 同一阶段真实执行失败的重试上限；等待状态不计次。 |
| 最大回退 | `2` 次 | 玩家操作中断、目标切换、非目标出锅和无进展终止后的重新制作上限；`0` 表示首次回退即暂停。 |

参数会在下一轮自动化轮询生效。并发过高可能抢占厨具，最大重试和最大回退用于限制异常情况下的重复尝试。

### 稀客自动化

可配置阶段：

- `自动完成订单`：一般订单满足条件时触发订单完成评价。
- `自动送达酒水`：按推荐酒水直接送达一般目标订单，送达成功后扣除库存。
- `自动开始料理`：按推荐料理选择可用厨具开始制作。
- `出锅后送达`：一般订单料理完成后直接送达目标订单，送达成功后释放厨具。
- `只处理收藏料理`：自动开始料理时只使用已收藏的料理方案。
- `只处理收藏酒水`：自动送达酒水时只使用已收藏的酒水。
- `出错时暂停`：遇到非临时错误后暂停当前订单。

一般稀客料理和酒水会分别直接送达：酒水会从库存创建后提交到桌面，料理会在出锅后提交到桌面；只有料理和酒水都满足后才触发完整评价。血池地狱 BOSS 会先复核原订单料理/酒水、实际成品及当前目标签名；严格方案还要求双 Tag 全部命中，受控推进方案则允许精确原订单料理在 Tag 可读但未全命中时继续。酒水仍可由自动化或玩家完成；匹配料理出锅后，只有 `出锅后送达` 与 `自动完成订单` 同时开启才执行专用无界面结算，任一开关关闭时由玩家通过游戏原生界面完成送达。

只开启 `自动开始料理`、关闭 `出锅后送达` 时，Mod 会登记精确锅次的手动交接回执，防止开锅响应丢失后再次扣料；该回执不会送达、入箱或复位厨具，成品留给玩家处理。普客的 `自动开始料理` / `自动送达料理` 采用相同语义。

稀客订单进入自动化时，会从页面首项对应的主执行方案锁定料理、加料和酒水。开锅或送酒后，即使库存变化让页面重新计算出新的首项，已开始的任务仍继续处理原来的锁定目标。

如果主执行方案是“偏好备选”料理，自动化状态中会保留该标识。开启 `只处理收藏料理` 或 `只处理收藏酒水` 后，系统会在自动化开始前优先把满足对应收藏条件的可执行方案作为主方案；没有满足条件的方案时，不会另行扫描页面中隐藏的后续目标来执行对应动作。

如果厨具或伙伴效果让最终出锅结果变成黑暗料理或其他非目标料理，或目标订单连续不可达，自动化会将该成品放入保温箱，并在下一轮重新确认目标料理。该次制作已消耗的材料不会恢复。

上述回退只在“成品明确不匹配”时继续，并受 `最大回退` 限制；达到上限后暂停对应订单。特殊经营成品 Tag 容器或 Tag 名无法读取时，Mod 会把成品放入保温箱并立即暂停该订单，不把运行时能力故障当作配方失败反复开锅。

### 普客自动化

需要先开启 `启用普客处理`，再配置阶段：

- `自动送达酒水`：按一般普客订单酒水送达并扣除库存。
- `自动开始料理`：按普客订单所需料理选择可用厨具开始制作。
- `自动送达料理`：一般普客料理完成后直接送达订单，送达成功后释放厨具。
- `自动完成订单`：一般普客料理和酒水都送达、订单进入待评价状态后触发游戏评价流程。
- `出错时暂停`：遇到非临时错误后只暂停对应普客订单。

普客会按首次出现顺序并发处理未评价订单。每笔订单独立记录送酒、开锅、送料理、待评价、已评价和暂停状态；同类厨具存在多个、同桌换单或同菜多单时，Mod 会尽量避免重复开锅和串单。

显示在普客区域的血池地狱 BOSS 订单仍使用挑战专用边界：Mod 会优先使用双 Tag 严格方案，严格无解且原订单通过全部硬门禁时才标记为受控推进；受控方案可能造成较低伤害并增加狂暴。Mod 可以自动推荐、送酒和开锅；匹配成品完成后，只有 `自动送达料理` 与 `自动完成订单` 同时开启才执行专用无界面结算，任一开关关闭时由玩家通过游戏原生界面送达最终料理。

自动直送的每次开锅都会绑定 `CookController.SetCook` 产生的精确锅次和当前厨具内容代际。Mod 只被动观察游戏原生的 `SetCook`、`Extract` 和厨具内容换入 `Store`；除正常自动开锅使用 `SetCook` 外，不会主动调用或重放 `Extract`、`Store`、`FinishCooking`，也不读取或跟踪玩家托盘。同一锅次的原生完成流程可以替换最终成品；成品经原生流程离开厨具或被新内容替换后，旧任务只释放自身，不会送达、存储或清理不再属于它的成品。自动送达开启且订单仍缺料理时，前端会在最大回退次数内按当前方案重新准备；玩家正常取出成品后，即使游戏仍保留上一份配方信息，只要厨具已空闲且取出过程完整结束，自动化也能重新使用该厨具。原成品若仍由游戏保留，重新准备可能再次消耗材料，Mod 不会读取、移动或删除它。自动送达关闭时仍保持同一订单的手动交接回执，但成品离开厨具后不继续占用该厨具的自动化预约。

### QTE 奖励结算

开启任一 `自动开始料理` 后，Mod 会固定尝试完成原生 QTE 奖励结算。该流程不会打开游戏音游面板；若游戏版本变动导致入口不可用，会在自动化状态中显示诊断信息，但不会中断已开始的料理。

### 预约、等待和回退

稀客和普客会共用本轮物理厨具预约表。每个控制器以本轮索引、原生实体身份和物理坐标共同预约，一台支持多种类型的厨具在同一轮只会占用一次；快照只在完整读取时形成自动化槽位。真正调用 `SetCook` 前，后端会重新读取同一字典和特殊事件锁定坐标，复核三重身份、`CouldOpen` 与锁定状态；任何漂移只返回局部等待，不扫描或改选其他控制器。排序靠前的订单没有对应可用槽位时，后续能使用其他厨具类型的订单仍可执行；厨具只是被预约、占用或暂时锁定时，不增加阶段重试次数。

经营中页的 `诊断` 视图会显示按当前完整快照推导的预计厨具占用，便于判断自动化是否因为厨具容量不足而等待。特殊经营中被规则拦截的普客订单会单独显示为未占用厨具，不计入预计容量。厨具暂忙会按后端给出的退避时间继续等待，不增加也不清零既有失败次数；订单对象暂不可读、桌面显示暂不可写等执行失败仍按各自结构化结果处理。普通等待不会伪装成阶段进展，游戏暂停期间也不累计料理停滞或送达超时。材料不足、无可用推荐、收藏料理或收藏酒水限定不满足等情况视为硬错误。

非目标出锅和目标连续不可达属于有界可恢复状态：Mod 会通过游戏原生 `StoreFood` 入口将成品放入保温箱，前端会回到确认料理阶段重新调度，并在达到最大回退次数后暂停对应订单。Mod 以保温箱中是否存在同一成品对象确认提交，即使原生回调后半段抛错也不会重复入箱；正常送达同样只提交一次。提交后只重试原锅次厨具复位，且必须确认厨具为空闲、成品和配方字段均已清空。无法确认提交或复位时保留现场并阻塞该订单。特殊经营成品 Tag 读取失败会立即暂停，不继续重试。

单笔订单的普通执行失败暂停后，可在状态卡片中点击 `重试`；若状态明显过期，可点击 `重置` 重新判断。达到最大回退次数后，`重试` 会保留已经确认的料理、酒水和订单事实，并重新开放一轮相同上限的回退额度；`重置` 则丢弃该订单的前端执行状态，按游戏当前事实从头判断。开锅、送达、入箱、订单评价或厨具复位存在不确定副作用时，Mod 会在同一订单的所有后续入口前保持安全栅栏；普通重试、阶段开关、总开关、断线和控制权转移都不会清除。先在游戏中确认厨具、保温箱、订单和库存现场，再从订单卡片或“待人工确认”列表点击 `确认已处理`；栅栏在 Mod 确认 ACK 后按既有状态恢复。血池地狱因阶段开关关闭而进入的正常人工交接不属于不确定事务；专用结算一旦进入不可逆阶段却无法确认结果，则保留终止栅栏且不自动重放。

## 游戏界面辅助

`游戏界面置顶推荐（实验性）` 开启后，打开游戏的料理选择面板或酒水架时，Mod 会尝试把当前目标订单主执行方案中尚未送达的料理、所需材料和酒水排到列表前方，并让由 Mod 置顶的目标列表项显示黄色脉冲高亮。料理送达后会撤销该料理、材料和目标厨具提示；酒水送达后会撤销酒水提示。当前订单全部送达或已结束时会先清空旧目标，再根据最新推荐切换到下一笔仍待处理的订单，不会在两笔订单之间继续显示上一单。多笔订单并存时，普通经营先选择主执行方案为任务方案的订单，再使用当前订单排序；特殊经营可跳过没有主执行方案的订单，取当前排序中第一笔有主方案的订单。选中订单后，页面料理与酒水首项、自动化开始时的选择、游戏界面置顶、列表高亮、厨具高亮和桌位高亮只使用同一组主方案，不会各自扫描后续方案。若目标在对应列表已经打开后发生变化，Mod 会按目标代际去重，并在 Unity 主线程只执行一次安全刷新；不会为此扫描面板、轮询界面或接管面板打开流程。该开关本身只调整列表顺序和可见提示，不自动点击，也不修改库存。

`点击推荐料理时自动加入加料（实验性）` 默认关闭，并且只在游戏界面置顶推荐同时开启时生效。玩家确认当前置顶料理后，Mod 只在面板仍是该配方的精确原生基础食材、加料后不超过五格、库存与原生倍率完整可读、经营及源订单 revision 未变化时，使用游戏原生库存入口一次扣除加料并把精确加料序列写入当前选择。任一条件不成立时保持原生行为；不可逆调用结果不确定时不自动重试或猜测回滚。

置顶或高亮失效时，先开启 `显示调试信息`，分别打开游戏的料理、材料和酒水列表复现。然后在 `经营中 -> 诊断` 复制完整的界面置顶状态，并连同总日志或诊断包一起提供。多个游戏原生收藏或任务材料仍会遵循游戏自身的排序规则；诊断显示目标已命中也不等于它一定是唯一的原生收藏项。

`目标厨具高亮（实验性）` 可独立开启。开启后，当前稀客订单尚未送达的主方案料理如果有目标厨具，Mod 会尝试让经营场景中对应已摆放厨具显示黄色脉冲高亮；料理送达、订单结束或当前没有可用目标时立即恢复原色。特殊经营下高亮目标与游戏界面置顶使用同一主方案。该开关只控制场景厨具；列表项高亮由游戏界面置顶开关自动控制。该功能只改变视觉提示，不会开始制作或修改库存。

`目标桌位高亮（实验性）` 默认关闭并可独立开启。Mod 通过游戏原生桌位索引定位当前目标订单，并使用独立于玩家光标的私有游戏原生样式提示；不会修改顾客、玩家光标或游戏共享 painter。订单结束、目标切换、开关关闭或经营进入结算时立即撤销，无法精确读取桌位或视觉资源时只在诊断中报告并停止该提示。

经营开始结算后，本轮自动化、游戏界面置顶、列表/厨具高亮和桌位 stencil 会立即停止，仍可安全访问的高亮对象会恢复或销毁，本轮目标和未完成任务也会失效。下一次经营会重新生成目标，不会沿用上一场的订单或高亮状态。

## 独立伴随窗口

伴随窗口会在 Mod 加载后自动启动。它是一个独立桌面窗口，可以移动、缩放和置顶，不受游戏窗口边界限制，并会保存普通窗口的位置、大小和最大化状态。最小化或关闭到托盘只影响当前运行，不会让下次启动保持最小化或隐藏。

窗口关闭按钮默认隐藏到系统托盘，而不是直接退出。可以通过以下方式重新打开：

- 在游戏内按 `F8` 或 `RS Click`。
- 使用系统托盘菜单 `显示 mystia-steward-companion`。
- 再次双击 `mystia-steward-companion.exe`。

如果独立窗口当前获得焦点，再按 `F8` 或 `RS Click` 会按 `设置 -> 窗口 -> 焦点切换` 的配置切回游戏：默认会隐藏伴随窗口，也可以改为保持伴随窗口悬浮、只切回游戏焦点。保持悬浮模式更适合配合透明度常驻查看；若游戏使用独占全屏，置顶效果可能受 Windows 窗口管理限制，建议使用窗口化或无边框窗口化。切换冷却只从一次实际完成的窗口切换开始计算；聚焦或显示失败不会占用下一次有效重试。

开启 `鼠标穿透锁定` 后，伴随窗口会忽略鼠标点击，便于把窗口悬浮在游戏上方查看但继续操作游戏。需要恢复窗口操作时，按 `F10` 关闭穿透，或通过托盘菜单关闭。`F8`、`RS Click`、托盘 `显示` 和托盘 `重连游戏` 都会自动关闭鼠标穿透锁定，避免窗口被找回后仍无法用鼠标操作。

### 同机连接

伴随窗口同机使用时会从游戏启动参数接收本地 API Token。若直接双击 `mystia-steward-companion.exe`，窗口会停留在未授权状态；需要连接游戏时，从游戏内按 `F8` 或托盘菜单唤起，已有窗口会接收当前游戏连接信息并自动刷新。修改 `IP:Port` 或 Token 后需要点击 `连接` 才会应用，连接失败时会逐步放慢重试，也可以点击 `停止` 暂停自动重连。

### 另一台设备连接（Windows / Android）

以下说明以 A 设备运行游戏和 Mod、B 设备只运行伴随窗口为例。两台设备需要在同一个可信局域网内，例如同一路由器下的有线或 Wi-Fi 网络。

A 设备操作：

1. 按前文安装 BepInEx #783 和 `mystia-steward-companion-bepinex.zip`。
2. 启动游戏并读取存档，等待伴随窗口自动打开；如果窗口未显示，按 `F8`。
3. 进入 `设置 -> 连接`。
4. 开启 `允许局域网设备连接`。开关会立即应用；只有修改 `LAN 监听地址` 时才需要点击 `应用`。
5. 确认 `LAN 状态` 显示已开启。优先复制标记为推荐且与 B 设备处于同一网段的地址，再复制 Token；存在多个候选时可以逐项复制测试。
6. 如果没有生成地址，先确认 A 设备有可用的局域网 IPv4，例如 `192.168.x.x`、`10.x.x.x` 或 `172.16.x.x` 到 `172.31.x.x`。多网卡、虚拟网卡或 VPN 环境仍可在 `LAN 监听地址` 中填写与 B 设备同网段、且属于 A 设备活动网卡的局域网 IPv4。
7. 首次开启或更换端口后，如果 B 设备连接超时，在 Windows 防火墙中允许游戏 EXE 接收 `32145` 端口入站；listener 运行在游戏进程内，不是伴随窗口进程。

B 设备操作：

1. Windows 设备从 Release 下载 `mystia-steward-companion-companion-windows-x64.exe`，下载后直接双击运行；如果当前版本还没有独立 EXE，也可以从完整 Mod 包的 `mystia-steward-companion/companion/` 目录取出 `mystia-steward-companion.exe`。
2. Android 设备从 Release 下载对应 CPU 架构的 APK 并安装。普通手机和平板优先选择 `mystia-steward-companion-android-arm64-v8a.apk`，旧设备再选择 `mystia-steward-companion-android-armeabi-v7a.apk`。若系统提示未知来源，需要只对本次下载来源临时允许安装。
3. 启动 B 设备上的伴随窗口。
4. 在窗口顶部连接区填写 A 设备复制出的 `LAN 地址`，例如 `http://192.168.1.20:32145`。
5. 填写 A 设备复制出的 Token。
6. 点击 `连接`，等待顶部连接状态变为已连接。

连接限制和排查：

- A 设备本机地址 `http://127.0.0.1:32145` 始终保留。即使 LAN 配置错误，仍可在 A 设备本机回到 `设置 -> 连接` 修改。
- B 设备不能使用 `127.0.0.1` 连接 A 设备，因为它只代表 B 设备自己。
- 不要填写 `0.0.0.0`，也不要通过公网端口映射暴露本地 API。
- 除 `/health` 外，局域网访问都需要 Token。Token 错误通常表现为未授权或连接后无法读取数据。
- B 设备浏览器可先访问 `http://A设备局域网地址:32145/health`：能看到 JSON 说明地址、路由和防火墙基本可达；浏览器也超时时，优先检查地址、游戏 EXE 入站规则、访客网络和 AP/client isolation。
- 连接配置和 Token 重置只能在 A 设备本机伴随窗口操作，B 设备不能远程修改这些安全配置。
- `F8`、`RS Click` 和自动启动只控制 A 设备本机窗口，不能远程唤起 B 设备窗口。
- 多个伴随窗口可以同时连接查看；自动化同一时间只允许一个窗口取得控制权，未取得控制权的窗口不会执行自动化动作。
- Android 版没有桌面托盘、置顶、鼠标穿透、窗口焦点切换和游戏关闭自动退出能力；这些能力只适用于 A 设备本机的 Windows 伴随窗口。
- Android 版支持竖屏和横屏；手机竖屏下顶部页签栏可横向滑动，焦点或当前页签会自动滚入可视区域，平板和横屏会尽量接近桌面布局；内容会避开系统状态栏和导航栏安全区域。

A 设备本机 Windows 伴随窗口在游戏关闭或 Mod 卸载时会自动退出；B 设备独立窗口和 Android 版会保留界面并进入重连状态。断线后窗口只保留最近一次只读数据用于查看，并按递增间隔重试带 Token 的完整快照；只有快照成功返回后才恢复“已连接”及自动化、置顶目标发布等后台动作。`/health` 仅用于人工检查地址和防火墙是否可达，不能证明 Token、快照或自动化控制面可用。

## 配置与数据位置

主配置文件：

```text
BepInEx/config/com.tyukki.mystia-steward-companion.cfg
```

常用用户数据：

```text
BepInEx/config/MystiaStewardCompanion/favorites.json
BepInEx/config/MystiaStewardCompanion/custom-recipes.json
BepInEx/config/MystiaStewardCompanion/aggregate-mod.log
```

常用配置项：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `ToggleKey` | `F8` | 游戏与独立窗口焦点切换热键。 |
| `ControllerToggleKey` | `JoystickButton9` | 手柄焦点切换热键，常见映射为 `RS Click`。 |
| `Companion.AutoLaunch` | `true` | 插件加载后自动启动伴随窗口。 |
| `Companion.ExecutablePath` | 空 | 伴随窗口可执行文件路径；留空时自动查找。 |
| `LocalApi.AllowLanConnections` | `false` | 是否允许可信局域网设备连接；本机回环连接始终启用。 |
| `LocalApi.LanHost` | `auto` | LAN 监听地址；`auto` 会监听检测到的私网 IPv4，也可指定本机私网 IPv4。 |
| `LocalApi.Port` | `32145` | 本地 API 端口。 |
| `Diagnostics.EnableAggregateModLog` | `false` | 是否写入总日志。启用后统一记录 BepInEx/Unity 事件、自动化、经营诊断和运行时数据诊断。 |
| `Diagnostics.AggregateModLogPath` | 空 | 总日志路径；留空时写入 `BepInEx/config/MystiaStewardCompanion/aggregate-mod.log`。 |
| `Diagnostics.AggregateModLogMaxFileCount` | `30` | 总日志最多保留的文件数，包含当前文件；每个文件 10 MB，默认约 300 MB。 |
| `Diagnostics.ShowBepInExConsoleOnStartup` | `false` | 是否在 Mod 加载时自动显示 BepInEx 控制台，仅用于本机排查。 |
| `SetConsoleUtf8` | `true` | Mod 加载后尝试把 Windows 控制台切换到 UTF-8。 |

如果从旧版本升级，Mod 会在新配置不存在时自动复制旧配置到当前文件名。

## 日志与诊断

普通使用不需要开启诊断。遇到识别、推荐或自动化问题时，建议按以下顺序收集信息：

1. 打开 `设置 -> 窗口 -> 显示调试信息`。
2. 进入 `日志` 页，开启总日志。
3. 复现问题。
4. 导出诊断包，或提供 `aggregate-mod.log` 当前文件和相关分片。

总日志默认关闭。开启后会监听 BepInEx 的所有日志源，每条记录带时间、级别、来源和线程标注，并写入 `BepInEx/config/MystiaStewardCompanion/aggregate-mod.log`。自动化动作、前端自动化候选跳过原因、经营扫描候选、运行时固定数据快照都会以不同 channel 写入同一组总日志文件。订单相关自动化日志会带 `trace=` 字段；该字段与经营中页显示的订单日志标识一致。单个文件达到 10 MB 后会拆分为 `aggregate-mod.1.log`、`aggregate-mod.2.log` 等递增文件；默认保留 30 个文件，约 300 MB，可在日志页或 `Diagnostics.AggregateModLogMaxFileCount` 调整。排查结束后建议关闭，避免长期写入占用磁盘。

如果总日志开启期间由外部删除或移走当前 `aggregate-mod.log`，Mod 会在下一条日志写入前释放失去路径的旧句柄、重建原路径，并在新文件写入恢复边界。

`aggregate-mod.log` 的分片上限不适用于 BepInEx/Unity 共享的 `BepInEx/LogOutput.log`、`output_log.txt` 或 `Player.log`。如果共享日志异常变大，先退出游戏，再保留末尾少量日志用于排查并删除大文件；Mod 不会擅自截断其他 Mod 共同使用的日志。

日志页的控制台按钮只在游戏电脑本机可用。显示时会按需创建控制台并保持 BepInEx 日志监听；隐藏时只隐藏窗口，不释放共享控制台或中断日志。每次显隐成功后会立即写入 `Diagnostics.ShowBepInExConsoleOnStartup`，作为下次启动偏好，但不会修改全局 `BepInEx.cfg`。如果全局配置已经要求 BepInEx 启动时显示控制台，Mod 默认设置不会覆盖它。为避免误关闭游戏进程，由 Mod 新建的控制台会禁用窗口关闭命令，请使用日志页按钮隐藏。

## 故障排查

### `F8` 无法打开独立窗口

确认 `mystia-steward-companion.exe` 位于：

```text
BepInEx/plugins/mystia-steward-companion/companion/
```

如果放在其他位置，请在 `Companion.ExecutablePath` 中填写绝对路径。若窗口已打开，`F8` 会在游戏和独立窗口之间切换。

### 伴随窗口鼠标点不到

通常是开启了鼠标穿透锁定。按 `F10` 关闭，或通过托盘菜单选择 `关闭鼠标穿透`。

### 一直显示运行时数据不可用

先确认已经进入游戏并读取存档。若仍不可用，开启 `显示调试信息`，进入 `日志` 页开启总日志并导出诊断包。

### 经营中没有稀客或点单

确认游戏内稀客已经入座并完成点单。若仍不显示，开启 `显示调试信息` 和总日志，查看经营中页扫描状态并导出诊断包。

### 自动化卡住或重复等待

先进入经营中页的 `自动化` 视图查看对应订单状态和自动化详情，再进入 `诊断` 视图查看预计厨具占用与未占用原因。常见原因包括厨具占用或冻结、材料不足、订单或桌面对象暂不可读、推荐为空、收藏料理或收藏酒水限定不满足；特殊经营预计差评、目标不一致或回调链不完整的订单会显示为未占用厨具。若厨具或伙伴效果产出黑暗料理/非目标料理，或目标订单连续不可达，状态会显示已放入保温箱并重新尝试。普通失败可对单笔订单点击 `重试` 或 `重置`；出现 `需人工确认` 时先处理游戏现场，再点击 `确认已处理`，不要反复开关阶段或总开关。

### 夜间经营订单较多时卡顿

先开启 `显示调试信息`，在概览页或经营中页的 `诊断` 视图查看快照耗时。若卡顿同时伴随多笔订单自动化，建议临时降低稀客并发或普客并发，或关闭暂时不需要的自动化阶段。仍无法定位时，到日志页开启总日志并复现，再导出诊断包或提供总日志文件，同时记录当时稀客/普客订单数量和开启的自动化阶段。

### 启动时仍短暂出现控制台

控制台可能由 BepInEx 在 Mod 加载前创建，因此 Mod 无法阻止 preloader 阶段的窗口或早期输出。进入伴随窗口后，可在本机日志页隐藏当前控制台；若希望下次从进程启动起不创建窗口，需要关闭 BepInEx 全局控制台配置。Mod 不改写全局 `BepInEx.cfg`，也不会释放其他插件共用的控制台。

### 控制台早期中文乱码

Mod 只能在自身加载后切换 UTF-8，不能修复 BepInEx preloader 已经输出的日志。日常建议忽略控制台早期输出；需要排查 Mod 运行期问题时开启总日志。

### 想重置 Mod 设置

关闭游戏和伴随窗口后，按需要删除以下内容：

- 重置插件配置：`BepInEx/config/com.tyukki.mystia-steward-companion.cfg`
- 重置收藏和自动化日志：`BepInEx/config/MystiaStewardCompanion/`
- 重置伴随窗口位置、大小和最大化状态：`%APPDATA%\com.tyukki.mystia-steward-companion`
- 重置伴随窗口界面偏好：`%LOCALAPPDATA%\com.tyukki.mystia-steward-companion`

删除后下次启动会重新生成默认配置。
