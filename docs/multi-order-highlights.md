# 多订单高亮与稳定分色

更新：2026-11-06。

## 使用方式

进入“扩展 → 游戏界面辅助”，开启共享总开关，再分别启停“普客辅助”和“稀客辅助”。分类关闭时整类列表置顶、配方变体、厨具/座位/订单高亮停止，另一类不受影响；各分项与颜色保留，关闭期间仍可编辑。普客、稀客各有“辅助订单与颜色”数量（1–3，默认2）和颜色选择器，一种颜色对应该类一笔辅助订单；不再另设“同时辅助订单”。普客预设为蓝、青绿、蓝紫等冷色，稀客为金黄、珊瑚、玫红等暖色，便于分辨类别。同类颜色必须互不重复，跨类可以相同。候选沿用任务、特殊经营及稀客调度优先顺序；只为前N笔合法候选分配N种颜色，暂停、已送齐或无有效方案的订单不占名额。超出上限的订单保持显示，暂不辅助；名额空出后补入下一单，仍入选的订单保留颜色。改变颜色数量会同步改变辅助上限。

经营订单、自动化状态与专注页沿用同一颜色；未入选订单使用中性背景，游戏辅助关闭时仍保留入选订单的客户端底色。颜色表达辅助身份，不代替执行许可或就绪状态，也不限制自动化并发。稀客调度暂停的订单不参与辅助候选；实际在做的订单仍由精确任务身份保护。

## 身份、共享与生命周期

- C# 唯一分配器按经营代次、客人类型、追踪号、订单生命周期以及普客原生订单键固定槽位。同一入选集合换推荐、换桌或重排不重新分配；优先级导致候选退出时释放其颜色，仍入选者保持原色。
- 订单明确结束后释放槽位，同桌的新订单是新身份。读取或稀客调度集合未确认时不把空结果当完成；歧义身份不显示并保留已知槽位，避免恢复后抢色。分配先在轻量副本上计算，最终帧校验通过才提交，迟到的旧刷新结果不能释放当前颜色。
- 每笔目标携带全局唯一 `colorSlot`（0–7），原生资源声明使用八位集合；类别内颜色序号唯一，不取模复用。跨类别同色仍逐笔撤销，修改普客颜色不改变稀客颜色，反之亦然。座位和左下订单正文采用固定透明度，不再明暗呼吸；同一表面的多声明颜色仍按每槽1.5秒、末0.3秒平滑过渡轮换，单声明不随时间变化。订单背景保持原九宫格尺寸并裁掉桌号上部，不能通过缩图把顶部造型移入正文。
- 厨具、料理、追加食材与酒水背景的左右顺序按订单产生先后排列，与可复用的颜色槽位分离。已有订单保持原色；例如蓝、黄、红、绿中的蓝单完成后，新单复用蓝色，排列变为黄、红、绿、蓝。普客和稀客使用同一生命周期顺序；单个物品只显示关联订单。同色合并时，以仍关联该物品的最早订单确定位置。
- 目标物品的置顶顺序也按点单先后：料理和酒水在各自列表中排序，食材保留游戏的分类列，在分类内部排序。共用物品以最早仍需要它的订单决定位置；同一料理的不同加料方案分别匹配订单，原生非目标条目保持相对顺序。
- 厨具沿精确摆放区域的原生选区形状显示分色背景，保留实际精灵网格和透明轮廓，多个颜色左右均分并延伸到桌沿；使用白色 alpha 遮罩提升选色对比度，避免桌面棕色压暗。每台厨具的背景两侧带细暗边，区分相邻摆放位置，不覆盖锅体。不再使用按格距推算的左侧小色块。同色声明只在显示时合并，最后一笔同色声明撤回才移除该颜色。原厨具、蒸汽和成品图像保持原样，不替换游戏交互 Tile 或共享精灵。
- 料理制作的料理/加料列表，以及酒水取用列表，直接对原背景 Image 生成的网格从左到右等宽着色，与厨具排列方向一致，不添加独立覆盖矩形。保留原背景纹理、透明边缘、九宫格及原生遮罩，物品图标、数量和文字维持原有层级。颜色与完整订单声明绑定，游戏的选中、可用性、回调和滚动行为不变。所有当前待取酒水均参与置顶；同一种酒水合并成一条库存记录，已送达后撤回对应声明。
- 相同基础配方且追加食材次序完全相同的变体合并引用；基础配方或有序追加食材不同则独立。完成/暂停一笔只释放该笔声明，最后一个引用结束才恢复原界面。
- 资源查询索引在不可变目标集发布时建立；每帧查询与调色不创建 LINQ 闭包或临时集合。

## 配置与测试

共享 profile 当前为 schema 10，`normalGameUiEnabled`、`rareGameUiEnabled` 默认开启，全局 `gameUiEnabled` 默认关闭。`rareOrderHighlightPalette`、`normalOrderHighlightPalette` 为两个独立数组（各1–3种不重复的大写 `#RRGGBB`），数组长度同时决定辅助上限。新配置默认各两色，添加第三组时从对应冷/暖预设中补色；各类选择器提供八个快捷预设，仍可自定义。

历史数据按原版本严格验证后一次性迁移，保留有效的自定义偏好，不自动打开全局辅助；具体版本转换由[设备配置权威](local-api.md#设备配置权威)统一定义，本文不维护第二份迁移规则。在线只接受当前协议，客户端与Mod必须成套升级。全局八位声明槽是稳定身份的实现容量，不代表可配置八笔辅助订单；每类最多三笔，合计最多六笔。

非游戏测试入口：`tests/csharp-game-ui-targets`、`tests/csharp-business-host -- --ui-colors`、`tests/runtime-cooker-color-blocks`、`tests/runtime-list-color-blocks`、`tests/ui-pinning-runtime -- --color-blocks-only`及`--beverage-targets`、`tests/runtime-order-highlight`、`tests/runtime-throw-delivery-order-highlight`、`tests/runtime-seat-highlight`，以及Flutter游戏辅助配置/订单颜色组件测试。色块专项运行正式服务/布局/资源代码，Unity边界使用可观测替身，覆盖定位、图标层级、逐色撤销、对象复用、生命周期与无变化热帧分配；直接回调和酒水前缀专项不注入Harmony，也不能替代实际相机渲染验证。真实Harmony注入使用锁定.NET6 Docker入口，不以纯模型测试替代注入验证。实际结果记录于本机验收记录。
