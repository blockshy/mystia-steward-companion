# 游戏内专注显示

更新日期：2026-11-06

## 用户入口与范围

“经营 → 专注 → 专注显示”统一管理外部窗口和游戏内面板。游戏内显示默认关闭，沿用当前主设备专注页的内容选项与明暗主题，不再单独提供一组内容开关。面板以相同语义的订单底色卡片、客人头像、标题右侧状态、前缀和带图标签显示同一主方案的料理、配方、加料、厨具和酒水；顶部没有“专注·单数”或编辑提示。制作、送餐、评价、收藏按钮及窗口导航不复制到游戏内。

稀客和普客分别可隐藏；稀客优先默认关闭。订单按正式展示顺序合并，启用稀客调度时仍显示全部当前稀客，参与单按队列顺序在前，暂停单按首次观测顺序在后，先沿用稀客槽位排序，再将已确认暂停的订单统一排到所有非暂停订单之后；暂停尾排优先于稀客优先。精确确认暂停的订单在标题显示“调度暂停”，不因此恢复执行或游戏高亮。展示队列不完整、重复或跨代时，仅撤销队列排序，保留当前完整且身份唯一的现场订单；不能用旧订单补齐。主方案尚未匹配时保留制作字段占位，不借用同桌旧单的方案。

有效经营期间，开启的面板不因零订单或内容筛选后零行而销毁，保留位置、尺寸、背景、边框并显示“当前无可显示订单”。订单恢复时复用原节点和同代图标缓存；消失的旧卡片立即隐藏。停用功能、退出有效经营或经营代次失效时仍清理，不把过期订单留在画面中。

## 设置与保存

| 客户端设置 | 默认值 | 控件范围 |
| --- | --- | --- |
| 开启显示 | 关闭 | 开关 |
| 背景不透明度 | 72% | 0–100% |
| 内容不透明度 | 100% | 20–100% |
| 边框粗细 | 1 | 0–6 |
| 游戏内字号 | 16 | 12–24 |
| 水平/垂直位置 | 屏幕坐标 x=0.70 / y=0.12 | 可移动范围的0–100% |
| 宽度/高度 | 28% / 72% | 屏幕的10–100% |
| 列表位置 | 0% | 内容可滚动范围的0–100% |

所有调整都通过外部客户端完成，无需暂停游戏。位置和大小保存为屏幕归一化坐标，位置滑块将剩余可移动范围映射为0–100%，100%表示贴右/下边缘，不是屏幕坐标1。运行时按最小可读尺寸限制在视口内；长标签自然换行，超出高度的内容用外部“列表位置”查看。协议允许严格有效的更小非零尺寸，以保留已有布局，不把客户端10%的滑块下限当作磁盘迁移条件。

配置位于 `BepInEx/config/MystiaStewardCompanion/game-focus-overlay.json`，版本2；版本1严格验证后保留原字节到`.v1.bak`再迁移，沿用外观和布局。主设备本机内容偏好耐久保存后按修订同步，查看设备仍只改自己的本机显示。详细协议见[本地 API](local-api.md)。

配置损坏时保留原文件并关闭显示，明确提供恢复默认设置入口；不把未知文件自动改成空配置。普通“重置布局”恢复位置、尺寸和列表位置，保留其它设置。每次修改携带当前显示修订；冲突或未知回执仅补读，不能由轮询反复重发。

内容自动同步与手动外观设置可能同时完成。客户端在同一连接/游戏上下文中只接受不低于已知修订的回执；旧请求失败不能撤销较新的确认值。迟到读取使用最新确认状态决定是否同步，避免开关、位置或尺寸因网络返回顺序发生回跳。

## 交互与 Unity 边界

游戏内面板永久鼠标穿透，不创建输入Raycaster，不读取鼠标、滚轮、暂停或玩家输入开关，也不修改游戏输入。全部设置通过受主设备权限保护的本地API更新，Unity主线程按已确认设置绘制，因此取消暂停要求不会把同一次鼠标操作同时送给面板和游戏。

渲染使用私有UGUI Canvas、Text、Image/RawImage与RectMask2D，不克隆原生订单/菜单，不扫描场景。图标只使用已验证媒体缓存的精确`kind:id`键，后台读盘，主线程限量解码自有Texture；媒体代次撤销时丢弃旧图。所有Unity对象只在主线程创建、更新、销毁；停用或离开经营撤销面板。

## 数据与性能

后台从正式结果首个执行方案冻结结构化标签；主线程只对小型现场快照做精确联结。方案作用域包含经营代次、场景、目录签名和完整订单需求指纹，仅忽略采集来源、末次观察时刻、显示槽位与动态等待条比例。图片依赖按唯一目录的FoodId/RecipeId双键与当前媒体清单匹配；材料重复及原顺序保留，不按名称找图。复制稀客的普通订单使用明确客人图片命名空间。底色读取正式`orderColors`，不依赖游戏辅助开关；配色及媒体代次变化即使候选引用不变也会更新。黑暗料理使用真实生产基底或保温箱来源。

方案还复用`BusinessDisplayContext`的完整来源语义，包括游戏会话、白天代次、特殊经营目标/阶段以及主设备与主配置身份。目录先于快照签名变化也会撤销旧方案；现场订单仍可显示，制作字段回到占位。准备投影与正式发布分离，只有业务结果被接受后才发布面板方案。主线程按快照与轻量权威身份引用缓存来源，不读取完整设备配置，不把每次普通采样都当作来源失效。

设置关闭时不创建 Canvas/字体、不生成面板方案。稳定帧只核对引用与视口，不重复投影、测量或写文本；设置、快照或方案改变才重建。此只读投影不进入推荐输入签名，不申请自动化租约，不改变实际动作顺序。

## 验证边界

`tests/runtime-game-focus-overlay` 覆盖外部几何、卡片/图标/标签排版、透明度、永久穿透、缓存代次与回收及稳定帧分配。`tests/flutter-contracts/host` 的 `--game-focus-overlay`、`--game-focus-overlay-store` 与 `--rare-order-display` 分别验证生产投影、持久化/CAS和暂停订单显示边界；Flutter的专注设置、镜像布局与暂停订单组件测试覆盖内容同步、失败保留、修订不倒退及窄窗口/字号布局。

这些托管、组件及隔离HTTP验证不能替代原生Windows窗口、Android设备或真实Unity/IL2CPP/GPU验收；实际执行的测试范围应在相应交付记录中注明。
