# 伴随客户端 UI

更新：2026-10-23。唯一产品入口为 `apps/companion-flutter`。客户端使用 Flutter、Forui 和官方 animations，Windows 与 Android 共用页面；C# 负责全部推荐、排序、预算与自动化编排。

本页记录当前页面职责、共享组件与交互约束；用户操作见 [Mod 使用说明](../mods/bepinex/README.md)，协议、图像缓存和运行时算法分别见所属专题。文档不将历史修复过程作为现行操作步骤。

## 页面职责与导航

主导航可见顺序为总览、经营、推荐、扩展、数据、设置。旧页面持久化数字 ID 不变（设置4），数据新增5；手机选中位置和手柄循环按可见顺序映射，不能把位置当作持久化 ID。

| 入口 | 内容 |
| --- | --- |
| 总览 | 经营状态、今日供给与食材/酒水合并低库存表 |
| 经营 | 普客/稀客订单、主方案、自动化状态、本机专注，以及独立统计信息 |
| 推荐 | 普客/稀客查询、收藏、自定义配方双模式与绑定的启用/置顶/顺序，以及推荐偏好 |
| 扩展 | 常驻任务列表、稀客邀请、库存修改、自动化、游戏界面辅助页签，开关位于各模块内部 |
| 数据 | 料理/酒水只读图鉴，默认已解锁、可切未解锁/全部并搜索；资源管理 |
| 设置 | 连接/设备/同步、外观、整包更新、诊断、帮助 |

主工作区每页有稳定的独立语义边界，隐藏页显式排除读屏语义；页面仍保留状态、输入草稿和滚动，不靠关闭动画或卸载页面避免切换异常。语义标签统一当前字体的行度量，使中文、纯数字摘要与加粗指标共享真实首行基线；图片按同一首行居中，多行标签自然增高。

## 布局与信息层级

Windows 所有宽度均采用80逻辑像素窄侧栏，设置固定在侧栏底部；较矮窗口中其余主导航独立滚动。Android 采用六项底部导航与紧凑页头，横屏仍保留底部导航；软键盘出现时为正文避让并暂时隐藏底部导航，保留页面及输入状态。导航方式依据平台能力，不由窗口宽度猜测。顶部不插入全局消息条。底部显示连接、设备角色、客户端与 Mod 版本，断线标注上次连接版本；操作反馈优先显示错误。手机摘要保持一行，可点击查看完整只读状态。页内主标签固定在上方，Android 单行横向滚动并确保选中项可见，Windows 沿用自然换行；与搜索同排的次级标签在两个平台都独立横向滚动。帮助保留自己的文档目录；导航标签不与执行操作共用描边按钮。

列表/详情按工作区可用宽度分栏：至少740逻辑像素时，普通列表约290–360像素；经营与推荐的丰富摘要列表占可用宽度约一半，限制在360–560像素，其余分配给详情。较窄窗口单独展开详情，返回保留原列表滚动。手机横屏输入且剩余高度不足时，暂时收起页头与全局状态行；短列表不再用固定计数标题占据正文，计数保留读屏语义。经营详情优先显示订单需求、主方案解释和阻断原因，备选搭配与捕获诊断折叠；厨具占用统一在经营的统计信息页展示。列表按需构建，业务行以订单追踪ID与生命周期标识作为key，不因新快照自动切页或重新定位到首行。

相关页签与搜索使用共用 `PageToolbar`：推荐的料理/酒水类别、经营的订单方案/自动化状态，以及任务、邀请、库存的筛选页签与搜索同排。搜索最多152逻辑像素，窄正文按实际可用宽度收紧；页签区域独立滚动，不能把搜索挤出视口。刷新等短操作保留在同排，长提示与批量操作独立排列。帮助只有目录搜索与清除，不将搜索强塞进设置主导航。输入控制器由各页面持有，缩放与键盘收放不能丢失焦点、选区或输入法组合文本。

Windows 页面边距统一为24逻辑像素，不在640处切换；Android 正文边距16，系统状态/手势区背景和图标亮度跟随主题。按钮与输入高度遵循统一几何入口，不能由窗口宽度推断触屏。推荐条件、预算、评分方向、动态标签搜索及普通选择器弹层共用152逻辑像素目标宽度，更窄父约束仍可收紧；三个推荐条件含间距共472px，在最小Windows窗口保持同排。设置下拉右对齐，滑块保留足够轨道长度。手机经营页将顶部筛选、状态和阻断信息限制在可滚动控制区内，键盘或横屏时仍留出结果阅读空间。普客/稀客的结果筛选只匹配料理或酒水名称，收藏与自定义配方保留额外的客人名称匹配。

局域网网卡选择器是明确的例外：使用 `StewardSelect.popoverWidth = 360` 与 `wrapItems = true`，完整展示地址和网卡名称；弹层仍受视口、安全区和父级约束。此配置不改变其它选择器的默认宽度，也不通过缩小文字截断完整网卡身份。

### 文字与对齐

公共文字标准由 `ui/steward_style.dart` 与 Forui 主题共同提供：正文、设置标签、控件值13px/1.45，说明12px/1.45，分组标题15px、条目标题16px。按钮同样采用13px/1.45，实际高度由 `steward_controls.dart` 按平台基准和真实字体度量统一计算，详见下方交互控件尺寸标准。各页不因窗口宽度单独切换字号，自动化与游戏界面辅助不再增加独有居中宽度。`ModuleSwitchRow` 统一五模块的启用、范围和权限显示；说明保留在读屏和提示中。折叠头只关闭内部按压缩放，保留填色、键盘焦点和展开行为，使其始终与外边框贴合。Android状态条通常30px，高字号可自然增长，全文保留在详情。

`StewardBaselineRow` 让混合字号、字段前缀、模块启用/范围文字共享首行基线；`StewardFirstLineCenter` 以真实字体度量定位图标、状态点与装饰条，适应中文字体回退和150%字号，不使用固定top补偿。标签Wrap采用首行顶部对齐，同一行只混用相同内边距的标签外壳。滑块、色板、选择器等复合控件维持整块居中和原命中区。扩展仅将必要的中文读取状态发布到当前页头；正常ready/成功人数摘要静默，未知状态、旧数据受限原因、错误与重试入口不能被省略。

全局优先使用平台已有的 `Noto Sans SC`，缺少时依次回退 `Microsoft YaHei`、`Noto Sans CJK SC` 与系统 sans-serif；不改变字号、字重和行高，也不打包系统字体。汉字轮廓各有自然留白，标题末字不单独位移或裁切。

### 控件尺寸与输入

尺寸由 `ui/steward_controls.dart` 统一定义。页面只能组合组件，不再自行选择 Forui 的 sm/md/lg 来决定业务控件高度。标准依据控件职责区分，不能将只读标签、颜色样块或双行主导航机械地放大为输入框。

| 控件职责 | 统一规则 |
| --- | --- |
| 单行输入、下拉、搜索、确认/返回/新建按钮、页内 Tab | 实际框体桌面至少36、触屏至少44逻辑像素；13px正文、1.45行高，按真实字体和 TextScaler 测量后共同增长。 |
| 图标按钮、预设颜色操作 | 采用同高方形操作区；图标16px，业务颜色样块保持20/24px，不改变颜色值。 |
| 搜索弹层输入 | 与触发框及普通输入共用字段样式；外置标签、说明、错误不计入框体高度。 |
| 工具栏与对话框操作区 | 同排垂直居中，水平/换行间距8px；窄屏允许操作组换行，名称和图标不压缩。 |
| 模块开关、全选复选框 | 实际操作区至少44px，随公共高度增长；保留开关与复选图形的语义比例。 |
| 长按钮、帮助目录、业务列表 | 标准最小高度，长内容自然增高；不以固定最大高度裁切。 |
| 只读标签、状态、主导航 | 使用各自语义层级；状态12px，标签沿用 SemanticTag，主导航保留图标与文字两行。 |

`StewardButton`、`StewardIconButton`、`StewardField`、`StewardSelect` 及页签/颜色/动态标签共享几何入口。按钮状态变化只改变颜色，不缩放框体。输入和下拉的文本垂直居中，选择弹层的搜索框也按同一规则处理。几何修改只覆盖尺寸与文字度量，保留 `StewardPaint` 的填充/前景透明度、禁用颜色、焦点及输入控制器。

搜索、筛选与格式示例使用输入框内部占位提示，不占用工具栏上方空间；隐藏视觉标签后仍保留无障碍名称。配置名称保留可见标签；普通数值及权重使用右侧滑块、当前值与完整范围，键盘可精确一步调整。`SettingControlRow` 保持左侧说明、右侧控制区，窄屏和大字号允许说明换行，控件仍与开关同侧对齐。输入控制区与保存/查询按钮按实际桌面或触屏主题共用随字号增长的高度，嵌入工具栏的选择项移除页级底部留白。预算策略与推荐条件复用 `StewardSelect`；地点、客人及两类需求支持在下拉面板输入搜索，仅可选择当前合法项。高亮颜色提供预设色、二维饱和度/明度面板和色相选择，当前色及只读 HEX 靠右显示；对话框取消不提交，确认重新检查身份和编辑权限。校验错误单独放在整行下方，不参与输入框与按钮的对齐计算。

中文输入使用原生TextEditingController，后台刷新不覆盖输入中的composing区间。弹窗保留并恢复原焦点；库存和设备权威等操作先显示明确对象及影响。

### 表面、颜色与动画

浅暖纸色、棕红强调、深色主题和小圆角延续项目风格。分组使用柔和的半透明表面、标题带与边界；列表选择和详情区域有明确层次。经营语义标签结合颜色、图标和文字区分配方、基础材料、加料、厨具、酒水、需求与警告，不只依赖颜色。中文字体由平台提供，应用不分发商业字体。字号可调到150%；触屏控件至少44逻辑像素并随真实行高增长，不靠缩字提高密度。独立背景/内容不透明度仅在Windows生效：原生DWM按Flutter像素alpha合成，全窗alpha保持255，调低背景不会连带降低文字透明度。`StewardPaint` 统一管理填充/前景角色，Forui 控件从不透明主题派生交互状态，不允许整树内容 Opacity 或在自绘层覆盖用户因子；背景覆盖页面、字段、按钮、下拉/弹窗和选中面，内容覆盖文字/图标/边框。颜色选择器的真实色样与HSV画布保留原色。

Windows 标题栏保留系统绘制、拖动、贴靠及窗口按钮，底色、文字和外边框与客户端明暗主题同步，避免与暖纸/深棕内容区割裂。高对比度模式使用系统颜色；精确标题颜色需要 Windows 11，旧系统保留系统回退。系统按钮保持不透明，客户端背景/内容透明度仍分别作用于 Flutter 绘制区域。

官方animations只用于明确的页面变化，数据轮询不会触发页面动画。用户或系统要求减少动效时关闭转场。任何租约、ACK或游戏动作都不依赖动画完成回调。

主题扩展 `StewardPaint` 与 `StewardControlDensity` 按字段值比较；相同模型状态轮询不得重新启动 Forui 主题插值或复选框淡入。真实颜色、透明度、平台密度及选择变化仍正常响应。

## 页面活动与错误反馈

防抖、读取及更新中的短状态统一显示在当前主页面标题右侧，不在正文反复插入加载行；长状态单行省略，完整信息通过读屏与悬停提示提供。减少动态效果时使用静态等待图标。每页独立状态通道，隐藏页或迟到请求不能覆盖当前页头；页面卸载后清理自己的发布状态。经营列表、详情与专注中的参考/待更新状态只在页头汇总，不增减卡片提示行。无来源的临时业务信封不能清除已核验属于当前上下文的展示；连接、场景、配置、目录或逐单需求真正变化时仍撤销不匹配方案。详细错误与重试保留，连接和保存反馈仍由底部状态区负责。只读展示保留不改变实际执行权限。

用户提示描述当前状态、影响和可采取的操作。经营统计在“自动化状态”下使用“暂停原因”，将已知场景原因码转成中文，未知原因保持待确认；“安全屏障/栅栏”在普通界面称为“需要人工确认的事项”，明确不能用普通重试继续。“控制权/租约”按实际情形说明主设备连接、同步或操作权限，不能笼统替换成“自动化已关闭”。协议字段、日志与高级诊断保留准确技术标识，文案不参与权限判断，也不能把结果未知的操作描述为“未执行”。

`OrderHeading` / `ServiceOrderHeading` 将短进度放在订单标题右列，复用于订单方案列表、详情和专注；自动化诊断使用整行身份，阶段与进度各自分行。送达只能来自现场布尔事实，未知不能转换成待送。页面级刷新、读取、连接、保存和错误由 `PageActivityReporter` 上报到标题右侧，正文不重复插入提示行。`PageActivityChannel` 按发布者独立保存、去重并按错误/加载优先聚合，空值和卸载仅撤回本来源，TickerMode 隐藏子树停止发布。页头可点击只读详情并随当前状态更新，不承载业务写入回调；手机短横屏输入时若出现错误，仍保留去除上下边距的页头入口，不能随辅助区一起隐藏。人工屏障由经营页紧凑入口打开原确认流程。

## 料理、酒水与图像组件

料理与酒水通过项目公共展示组件复用于经营与推荐四类页签。名称、关键指标和配方分层排列；厨具/基础材料/加料使用语义标签，来源提供的标价/成本/利润/库存及匹配统计集中在“指标”行。`OrderTag` 与 `MenuMetric` 共用 `SemanticTag` 的字号、行高、内边距、圆角与图标尺寸，仅语义色与数值字重有所区别；匹配标签独立显示。来源适配与 Widget 分离，仅联结目录和观察库存，不计算业务结果。稀客推荐料理的 `allTags/cancelledTags` 与经营的 `activeTags/suppressedTags` 分别适配；稀客酒水 `matchedTags` 明确称为匹配标签，不当作全部生效标签。普客 `totalCoverage` 为命中标签总数，`coveredCustomerCount` 为覆盖人数。

共用菜单组件的摘要最多显示四个标签，其余数量统一用“+N”文字标签；省去装饰图标的宽度但保留同高、同首行基线和完整读屏语义，详情仍展示全部。静态属性及详情原“料理/酒水”前缀统一为“标签”；匹配、生效、目标与抵消的不同业务含义继续保留。

`MenuInfoGroup` 与 `MenuTagGroup` 统一外层和详情的短前缀及标签列。摘要最多四项，其余以同尺寸中性标签指向详情；详情完整保留来源顺序与重复项。匹配、目录标签、生效分别展示，只有明确同源的生效摘要和完整生效数组逐项一致才避免重复。逐客匹配数仅读取服务端计数，缺失显示未知；加料原因保留食材身份，完整说明段落不硬拆成标签。经营详情按料理和酒水分别定位，普通基础方案用 `MenuItemDivider` 细线分隔，原订单和特殊执行身份仍用文字标注。

`EntityImage` 通过当前宿主资源清单的命名空间与整数 ID 替换装饰图标：100% 字号下标签20px、名称28px，且只在组件内部应用一次 TextScaler。图片应用内容不透明度；加载、未知或损坏时同槽回退，不改变标签尺寸或重复名称语义。Food.id 与 Recipe.id 不互换；基础食材和厨具要求双键与当前唯一目录条目一致，食材长度与编号类型也一致，按原顺序保留重复项。原订单和客群匹配详情直接使用服务端 foodId/beverageId/customerId，禁止按名称猜图。

普通订单与自动化诊断的头像消费 `guestImageKind` / `guestImageId`：宿主核对实际客人派生类型与唯一目录身份后，分别指向 `rare-guest` 或 `normal-group`。因此复制的稀客不会因出现在普客通道而取同数字的普通客群头像；类型冲突、来源冲突或缺目录时回退通用图标。订单类型、`GuestId`、`OrderKey` 和执行门禁不随图片身份变化。

## 推荐、收藏与自定义配方

普客/稀客推荐页在有效条件确定后自动查询，短防抖合并条件变化，显示加载、后台计算、空结果和可重试错误。查询代次防止 A→B→A 的旧响应覆盖，隐藏页面撤销订阅；推荐专属错误不改变经营连接和执行租约。

稀客查询从当前客人的 `positiveTags`（排除动态流行标签）与 `beverageTags` 提供选项，选中值为目录中的标签字符串。切换客人或目录刷新后保留合法选择，无效项恢复到该列表首项；缺少合法标签时不发起查询。筛选与查询不会改变业务算法。

“推荐偏好”作为推荐主页面中的独立页签，承接原设置内推荐规则。评分模式固定四项预设并新增自定义，当前模式可见选中；固定预设不暴露权重编辑器。仅自定义允许调整参与、权重与方向；保存队列在执行时再次检查当前模式，防止已离开的权重控件迟到回调覆盖新预设。

排除资源采用可复用动态标签组件：搜索下拉仅提供未选目录项，候选和已选标签通过同一 `itemLeading` 按明确食材/酒水 ID 显示图片；已选项可移除，未知历史ID仍展示并可删除。共享保存门闩保护两种资源的嵌套配置，提交时合并最新配置，不乐观修改权威结果；连接、设备或配置边界变化后旧事件失效。

收藏料理通过持久记录 `recipeId` 联结目录 `id`；自定义通过 `foodId` 联结目录 `id`，不可误用其独立游戏配方编号 `recipeId`。自定义绑定始终显示料理内容，不能沿用上一个页签的酒水分类。目录缺失/歧义保留已保存名称或原始ID并提示未知；来源中的材料重复项保持顺序，库存 -1 显示无限，未知不伪造零。收藏与自定义没有实时推荐评分或生效标签，不在客户端补算。详情主要承载完整标签、逐客匹配、说明与人工操作，避免重写一套基础配方展示。

自定义新增/编辑的料理、稀客、追加食材候选及已选食材共用实体图片；厨具与基础材料只消费当前资源代次的双键配方依赖。重复基础材料保持顺序，未知历史追加食材保留精确编号与删除入口；名称相同不会合并身份，目录缺失不会按名称反查图片。

`CustomRecipesPanel` 独立承载双模式列表和编辑器。“料理模式”按 `foodId` 分组绑定稀客，“稀客模式”按 `customerId` 分组添加料理；每条记录在两种模式中都绑定明确客人与料理，并保留标签条件、加料和条目身份。模式是服务端保存的生效集合，不是本地浏览筛选；只当前模式且启用的记录参与计算，切换保留另一集合。合法旧版文件由 C# 一次迁入稀客模式，保留原身份、绑定、标记和顺序，客户端不复制或推导历史记录。编辑对话框固定打开时的连接、共享权限及模式修订；异步保存仍由现有写入门禁核验，过期编辑需重新打开。

模式选择使用 Forui 单选控件及选中背景、边框，始终最多一个选中。模块总开关关闭时保留模式偏好并明确显示未启用；选中项再次点击不提交，保存锁与渲染时连接/权威/模式修订共同阻止陈旧回调和重复写入。通用读取与保存反馈投影到页头，编辑器字段约束与具体校验仍留在操作上下文。

## 经营、专注与统计

经营主Tab依次为稀客、普客、专注、统计信息。订单页不再插入厨具汇总；统计使用实时现场订单投影，未知计数显示“—”，自动化数据仅在当前业务代有效时展示。厨具现场状态与本轮拟分配分区，不能把拟分配当作真实占用或跨类型累加多功能厨具。总览只保留经营/供给状态和合并低库存表。自动化配置、状态、暂停原因、待确认事项统一在统计页；事项按钮复用经营页既有确认弹窗，仍检查连接、权限与会话代次。当前厨具读取状态使用中文，原始诊断仅在展开详情中保留。

经营订单固定按首次观察到点单的时间排列，同刻按稳定身份排序；未知首次时间排在已知时间之后。专注页默认使用服务端的跨普客/稀客显示顺位合并两类订单；本机“稀客优先”默认关闭，开启后仅将稀客组放在普客组之前，各组内部仍保持服务端顺序，不恢复共享订单排序设置。自动化与游戏界面辅助仍独立保留特殊经营所需的执行优先级；列表位置不能作为执行许可。

经营桌号将非负 `deskCode` 加一用于列表、详情、筛选及确认文案，原始标识和请求参数不变；服务端已格式化的执行诊断标题不重复转换。点单、料理和酒水来自同一订单与主执行方案，不从任意候选补齐缺项。

新订单立即显示真实客人、桌号、点单及送达状态；列表、详情和专注对尚未返回的推荐字段使用静态等结构占位，不等待计时器、不播放高度展开动画，不填造料理、材料或图片身份。预留按实际字体、字号和图标槽测量，只有经历等待的订单保留这一布局下限，初次即有完整结果的订单维持原自然密度；专注只为已开启的字段预留。常见单行方案到达后保持下方位置，长名称、多材料或完整错误解释需要更多行时仍自然增高并可滚动，不裁切内容或承诺任意长文定高。读取错误与没有可用方案仍按真实结果显示；计算及参考状态继续由页头汇总，此布局不改变方案联结、执行或权限计算。

经营摘要只读取 C# 的第一项 `executionPlans` 或 `normalOrderDetailPlans`，不把独立候选拼成执行方案。稀客展示基础配方、加料、厨具、预算及特殊状态；普客区分原订单、当前实际方案和送达/评价，详情补充目标、生效/抵消标签、规则与阻断。缺失字段明确标为未知，不能由显示结果推断执行资格。

经营的“专注”页只重组实际订单的只读展示，稀客使用同一首个执行方案，普客使用实际执行料理/酒水，不从独立候选或原订单补造方案。`serviceFocusShowRare/Normal/OrderTags/Food/Ingredients/Extras/Cooker/Beverage` 分别保存本机显示项，缺省开启；`serviceFocusRareFirst` 保存默认关闭的本机稀客优先分组。桌号、客人、缺方案及必要阻断信息不随字段开关消失。偏好通过 `updateLocal` 合并持久化，不进入共享 profile，不改变租约或游戏动作权限；断线不展示缓存方案。专注与原列表通过保持节点的视图切换，返回保留原类型、筛选与浏览状态；`serviceFocusShowWindowUi` 默认开启，仅在经营专注前台为 false 时隐藏侧栏/底导航、页头、经营页签和状态栏；本机设置保持可访问，失败保留不含标题的紧凑入口。隐藏区排除焦点与页签登记，稳定子树保留状态。

经营使用“自动化状态”页签。订单身份独占标题，状态与阶段、送达进度分别分组；详情显示阶段耗时、重试/回滚、下一步、原因、处理目标、现场反馈与高级诊断。处理目标使用编排器投影的 `foodId` / `recipeId` / `extraIngredientIds` / `beverageId` 显示图片，基础材料与厨具仍通过双键依赖确认；`targetSource` 明示已锁定方案或原点料理目录配方。后者仅用于无锁定目标且原配方唯一确认的普通标准订单，不将特殊替换订单的原点单冒充目标，也不套用最新推荐。`foodDeliveryRequested` 等请求标记不等同于 `hasServedFood` 等观察事实。普客操作摘要与原订单之间保留分组留白。

经营的订单方案、自动化状态和专注卡片统一按业务通道读取 `rareTargetHighlightColor` / `normalTargetHighlightColor`，以低浓度底色区分稀客/普客，填充经过背景透明度通道。颜色不依据头像类型、当前游戏目标或执行权限；复制稀客提交的普通订单仍使用普客通道底色。`gameUiEnabled` 及辅助分项只影响游戏内效果，不控制窗口的订单分色；选择态、文字和必要警告保持各自语义。

## 扩展模块

任务列表、稀客邀请、库存修改的本机偏好键分别为 `missionListModuleEnabled`、`rareGuestInvitationModuleEnabled`、`inventoryEditorModuleEnabled`，缺省均为关闭。模块内部开关不要求主设备，忙碌或操作未完成时禁切；仅开启且当前可见时订阅。停用后保留当前页签、显示关闭说明并清除选择，隐藏页或关闭模块撤销读取订阅；异步确认返回时再次核对启用状态、页面可见性及写入权限。任务模块开关不改变共享 `missionRecipePriorityEnabled`。历史任务/邀请开关可迁移，库存是新增独立开关。

自动化和游戏界面辅助是独立扩展模块，分别由共享 `automationEnabled`、`gameUiEnabled` 总开关控制，离开页签不关闭效果。辅助总开关由 C# 执行门禁处理，关闭保留普客/稀客分项与颜色，查看设备不能改写。自动化并发分别位于普客/稀客步骤中，“同一步骤失败上限（共享）”和“重新安排次数上限（共享）”保留原共享字段，两区采用简短提示，完整计数、清零及同步规则保留帮助与代码说明。

### 任务与稀客邀请

任务采用文档式外层条目：标题、独立状态、来源字段、条件进度与逐条条件或触发说明。稀客邀请使用独立紧凑人物项目：头像、姓名与邀请按钮同排，邀请状态与羁绊同排，实时地点和读取状态相邻，完整邀请原因位于末行。卡片内边距10、相邻资料组间距4逻辑像素，不为短状态或操作额外预留整行；长姓名和原因自然换行，不能用固定卡高、缩小图片或压缩触屏命中区换取密度。两者不复用料理标签，不使用列表/详情结构，不补造服务端没有的字段。手机启用模块后采用紧凑开关与同排搜索/刷新，控制区最多占正文一半或280逻辑像素，其余筛选可滚动访问。库存点击名称或库存表头切换升降序，未知值始终后置，同值按稳定标识排序；排序只改变显示，不改变选择或服务端库存。

邀请地点与位置状态读取 `locationStatus` 及确切的地图名称/标识；不能把 `isCurrentScene=false`直接解释为其它地图。当前未登记和位置读取不可用分别显示，不能从稀客静态偏好地区补造实时位置。合并视觉字段后仍保留“实时地点”读屏名称，图片只按明确稀客ID加载。邀请说明保持独立标签列和内容列，长原因完整换行；失败与资格阻断不隐藏在展开操作中。按钮继续使用统一控件尺寸及父工作区提供的权限回调，状态文字为“可邀请”也不能恢复已被场景、身份或忙碌门禁禁用的操作。

邀请的羁绊筛选与批量按钮使用同一行：文字前缀在左，等级列表独立横滚，“邀请筛选范围”固定在右。等级控制器归页面持有，模型刷新不重置滚动和选择；确认与权限门禁保持原行为。设置辅助说明使用公共12px说明样式，错误保留13px正文，不用局部缩字解决窄宽。

可接取任务的完整非就绪只读DTO可携带运行时诊断。`AvailableMissionReadState` 仅识别该端点当前的完整合法形状，连接/查询/场景代次核对后才允许保留；正常等待以中文状态显示，真实故障保留诊断。其它资源及全部写入继续执行原有成功校验，未知或矛盾响应不能按就绪处理。

### 库存修改

库存修改的单选、全选和确认后复核共用可编辑性条件：精确唯一 ID、非负整数数量。`-1` 为无限库存，只读；其它非法值或未知数量不可提交。完整运行时与目录快照中，库存映射及可用 ID 集合合法一致时，可按生产稀疏编码补齐目录中省略的真实零库存；该投影不回写业务状态。数量轮询变为不可编辑即撤回勾选，确认期间发生变化不提交旧写入。操作提示按本次结果更新，失败清除旧成功提示，批量部分失败保留计数与原因且不自动重放。

库存条目分为独立选择列、资料区和数量操作区。选择列与表头全选同轴，相对整条垂直居中；图片、名称及轻量标签居于资料区，数量突出显示并提供独立−10/+10按钮。按钮不嵌在复选框事件区内，点击不会改变批量选择。长名称自然换行，不挤走数量、不压缩图片或复选框命中区；标签提供补充资料，不与库存数值争夺层级。缺少已验证图片时保留同尺寸通用图标，未知数量与无限库存明确区分。选中项使用浅色表面和边界，同时保留复选框状态，不能仅靠颜色表达选择。条目身份使用稳定的“资源类型 + ID”，不依赖名称或列表位置；筛选、排序和轮询更新不应让勾选或焦点错附到另一条目。表面、文字、图标和边框继续遵循现有背景/内容不透明度分层。

表头使用三态全选，仅覆盖当前分类及筛选内可编辑的唯一 ID；筛选外已选项保留并计数。目录消失、重复 ID、数量变为无限/未知、分类或连接身份变化时撤回无效选择。点击名称/库存切换升降序，未知值后置，同值按稳定身份排序。单项 −10/+10 不改变批量选择，0–9999 边界之外禁用；确认后再核对精确数量与权限，结果未知不重放。

## 数据与资源初始化

数据页包含料理、酒水、资源管理，前两页复用基础资料组件并各自保留筛选/搜索/详情状态；详情在上方一次完整显示标签，下方不重复，列表继续显示紧凑摘要；默认筛选已解锁，可切换未解锁或全部。料理使用 `inventoryReadReady` 为真的 `availableRecipeIds`（目录 foodId）；酒水使用独立完整的 `beverageUnlockReadReady` / `unlockedBeverageIds` 图鉴记录，不能用库存非零推导解锁。缺失、不完整、断线或非法编号保持未知，未知不进入已解锁/未解锁列表。图鉴不发推荐查询、不执行写操作，静态配方不展示方案专属的“加料”行。

图像由 Mod 首次加载初始化并缓存，不随客户端打包。`GameMediaController` 在每轮会话读取时核对状态及代次，完整验证清单后通过 `GameMediaScope` 同步提供 Provider；图片按需加载、最多四个真实 HTTP 在途请求，并校验长度、PNG 尺寸及 SHA256。连接、清单代次或读取失败会撤回图像与配方索引，迟到响应不能提交。资源未就绪时替换整个 Navigator 工作区，撤回已有弹窗和自动化租约。缓存核验、等待目录、实际提取、重读及失败统一使用独立初始化界面；`verifying` 明确表示核验缓存或同步目录，不冒充提取进度，也不在工作台页头与独立界面之间切换。完成前不挂载业务页面、表单或操作快捷键，完成后自动进入工作台。

旧缓存缺少启动凭据时，需进入存档完成一次完整确认；通过后原代补建凭据并复用已有图片。以后游戏版本、DLC 与资源身份未变化且缓存完整时，可在主菜单校验复用，无需先读档；这仍包含宿主对磁盘清单及全部 PNG 的校验，不是跳过检查。数据“资源管理”默认全部分类，可切换六类并按名称或编号搜索，筛选只作用于已验证清单，图片继续按可见项加载；重读仍限主设备。实现边界见[运行时图像资源](game-media.md)。详情可折叠分组在上下各保留12px阅读间距，客群标题和其标签间隔4px。

## 连接、设备与局域网

启动参数连接在进程内锁定地址、Token和连接名称，页面与模型写入入口共同限制；无参重试沿用原参数，可信原生激活仍可提供新参数。锁定不写入跨启动偏好，手动及保存来源保留原编辑流程。锁定只影响当前连接表单，不阻止本机主设备管理局域网服务；Token更新成功后，当前会话沿用原设备身份接续新凭据。

连接表单默认显示当前来源、地址和角色，手动或已保存来源通过“修改连接”显式编辑；启动参数连接只提供原参数重试。仅进入编辑时回填已保存 Token，默认掩码并可主动显示；更换地址会撤回尚未编辑的旧 Token。异步初始化和轮询不覆盖用户草稿、选区或输入法 composing；取消编辑不发送请求或断开当前会话，连接中禁止重复提交；仅首次数据读取成功才提示连接成功。来源按真实激活/恢复/手动路径记录，不从 Windows 平台或主设备角色猜测。

“设备与共享配置”按精确 `currentDeviceId` 标注本设备，与主设备角色分别判断。每个设备的设为主设备、同步主配置、忘记设备位于同一操作行；删除确认后再次核对精确身份与状态，只有当前主设备可忘记其他离线查看设备，不允许删除本设备、主设备、在线或歧义记录。

`SettingsLanSection` 是常驻分组。“刷新配置”只重新读取服务状态和网卡，不保存草稿；绑定地址仅从 `availableLanEndpoints` 唯一地址中选择，“自动（全部网卡）”表示全部符合条件的私有网卡。失效旧地址不冒充合法选项，须重新选择。Token 允许 8–128 个非空白可见 ASCII 字符，密码框复用公共尺寸、控制器与显隐按钮。

更改 Token 需确认，确认仅授权当时的连接、主设备权限、当前网卡、服务端基线及草稿。保存由 `updateLanConnection` 串行处理；只有明确回执后才持久化新凭据、回读确认并沿用原设备身份续接，未知结果不重放。局域网管理仅游戏电脑本机主设备可写；Token 回显不降低这些条件。后端配置事务与凭据交接见[本地 API](local-api.md)。

## 诊断与帮助

`SettingsRecentOperations` 显示本次运行最多 20 条实际动作的名称、时间及成功/失败/结果待确认状态。后台轮询和通用 notice 不构成操作记录，不能复制 Token、请求正文或原始异常；写入已确认但后续刷新失败，保留真实写入结果，不将其改写成未执行。

诊断页日志保留文件数为 1–30；控制台开关显示实际状态，不再重复显示启动偏好行。“刷新诊断”成对读取日志设置与诊断包，不因资源切换取消另一项订阅。包列表使用服务端提供的精确 `id`，显示文件名、大小、时间；读取失败撤回删除入口，不把错误伪装成空列表。“刷新列表”重新获取可用身份。

删除诊断包需主设备权限，确认期间模型、连接、文件身份或权限变化即取消。包列表和删除可经认证的远程连接使用；产品中的日志配置、导出、打开目录与控制台操作仍限制在本机。服务端按固定目录及已列举文件身份删除，边界见[可观测性](observability.md)与[本地 API](local-api.md)。

帮助由 `assets/help-content.json` 提供，保留既有稳定条目 ID，并按当前页面补充历史迁移、模块启停、专注、统计与数据等主题。分类具有ID、标题、说明；文章具有ID、标题、摘要、步骤及可选说明/注意。帮助浏览器对上述全部文本搜索，宽屏目录与正文并排、窄屏进入正文后返回目录；不依赖网络或游戏连接。新增帮助应以实际功能为依据，不恢复已移除的旧按钮说明。

帮助目录仅记录主动展开的分类，默认全收起；搜索临时展开匹配项，不改变用户展开选择。短高度时标题、搜索和返回入口随内容滚动，保留焦点与草稿；文章只说明真实现行入口，不让实现细节或已移除按钮占据用户步骤。

## 状态与动作边界

- `companion_protocol` 是不可变DTO和版本约束；`companion_client` 持有HTTP、设备CAS、租约与当前来源判定；`companion_platform` 提供原生窗口、输入和存储。
- `LiveWorkbenchModel` 是应用组合根；Widget只调用其已声明的操作。不把业务计算搬到Dart。
- 同一来源允许显示上次成功方案并提示刷新；来源变化立即清空。显示旧结果不等于持有执行资格。
- 自动化意图只有持久化共享配置 `automationEnabled` 一处来源。运行资格仍要求主设备、已确认且开启的配置、有效租约、当前业务快照和有效夜间生命周期。新身份默认配置关闭；既有设备重启、重连或切主后按已保存配置及完整门禁恢复。
- 写请求不自动重试。超时或断开导致结果未知时保留错误，并通过重新读取确认。
- Windows 恢复窗口位置时可能重入消息处理；平台初始化只对确切的原生初始化通道尚未注册错误做最多3秒的就绪等待，不重试存储写入或游戏操作。初始化失败按阶段保留，切页和外观保存不能清除；连接页重试先恢复本机身份，再连接：启动参数来源使用“重试连接”，人工来源使用“保存并连接”。相同凭据再次激活失联窗口时允许重新握手，自动化仍以已保存配置为准。
- Android进入后台停止续约并尽力释放；Windows隐藏托盘/失焦继续保持已有会话语义。
- 共享配置与本机外观分开保存；同步ACK必须在原子持久化与回读一致后发送。共享编辑串行出队时读取最新权威配置，评分目标仅按key合并叶字段；连接/设备改变或前一项结果未知会取消旧队列，不重放。外观滑块先本机预览并自动持久化，迟到失败仅回退自身尚未被新编辑替换的字段。
- 共享配置与设备存储使用 schema 4，评分模式明确区分四个固定预设与自定义。历史 schema 1/2/3 只经显式磁盘/checkpoint 迁移：先严格验证旧字段与服务端原哈希；若九项评分参数仍等于原预设则保留模式，否则迁为自定义并保留原值与顺序。schema 1/2 还移除旧订单排序字段，schema 1 按任一辅助分项是否开启确定游戏界面辅助总开关；其余已存在开关保留。服务端生成新的修订、哈希与待确认标识，主设备在重新落盘并 ACK 前不能写入；HTTP 不兼容旧配置格式，损坏或未来版本文件不覆盖。

## 快捷键与手柄

F8/RS与F10由Windows原生层处理。手柄方向/摇杆导航、A确认、B返回、LB/RB切换主页面、LT/RT切换当前横向页签。推荐列表中X调用当前聚焦行的收藏操作。失焦、重连或拔插后要求回中，长按只对方向导航重复，肩键和扳机每次按下仅切换一次。弹窗期间不切换底层页面。`GamepadNavigationController` 优先当前聚焦页签，否则可见主栏；隐藏/TickerMode禁用/非当前路由不能接收LT/RT，同轮切主页面后的扳机事件不重放。仅手柄输入时侧栏上下显示LB/RB、当前横向栏左右显示LT/RT，真实鼠标/触屏/键盘输入或失活事件撤回提示。

## 验证

`apps/companion-flutter/test/workbench_test.dart` 覆盖1280/640/390、150%字号、深色子页、10,000行按需构建与滚动保持、中文输入、辅设备禁写、库存确认/取消和断线不跳页。真实HTTP组合测试见同目录 `live_http_contract_test.dart`。

`field_alignment_test.dart` 比较仍保留的文本输入框与操作按钮边界，并检查数值/权重滑块、长名称与字号变化下的可用布局。

`extension_modules_test.dart` 覆盖模块缺省关闭、本机开关与共享配置分离、隐藏/停用撤销读取、关闭后确认不写入、操作期间禁切及1280/640/390和150%字号。

回归必须通过 `InputDecorator.containerOf` 获取真正绘制填充/边框的容器，与按钮 ShapeDecoration 比较；InputDecorator 自身仍是外壳，不能作为实际边框的替代。字段上下留白由共同高度减去真实行高计算，防止只有外壳等高。桌面/触屏与100%/150%字号覆盖实际中文字体；页面矩阵继续覆盖390/640/1280px、草稿、焦点、对话框和权限边界。原生最窄 Windows 与 Android 预览另行检查，不将组件测试称为真实游戏测试。

`settings_state_test.dart`、`settings_management_test.dart` 覆盖启动来源锁定、Token 回填/显隐、网卡菜单、草稿保留、设备删除、诊断记录及包管理；`help_browser_test.dart` 使用真实随包 JSON，覆盖搜索、默认收起、宽窄布局与返回。数据、专注、统计、图像与订单占位分别由对应组件和模型测试覆盖，逐条断言以测试源码为准。

原生 Windows 最窄窗口与 Android 设备检查需记录真实尺寸、系统版本、构建来源及操作范围。组件测试、离线合成预览、隔离 HTTP 和真实游戏证据分别记录；不能用成功构建或页面截图替代 Unity/IL2CPP 运行时行为验证。执行入口与边界见[验证指南](validation-guide.md)。
