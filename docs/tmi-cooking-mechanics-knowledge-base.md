# 东方夜雀食堂料理机制知识库

更新日期：2026-08-19

本文只记录已用于当前实现的游戏原生评价、料理 Tag 生成和压制机制。候选生成与排序见[推荐引擎](recommendation-engine.md)，运行时数据来源见[运行时数据 Provider](runtime-provider.md)，特殊挑战改判见[特殊经营规则](special-business-scenes-notes.md)。

## 评价名称

代码和技术文档统一使用游戏枚举语义：

| 代码名 | 用户可读名称 |
| --- | --- |
| `ExGood` | 完美 |
| `Good` | 满意 |
| `Normal` | 普通 |
| `Bad` | 不满 |
| `Exbad` / `ExBad` | 极差 |

颜色只是界面语义，不能作为逻辑名称或 identity。

## 标准稀客评价

标准稀客订单包含一个料理 Tag 和一个酒水 Tag 要求。料理与酒水命中的喜好/厌恶 Tag 共同计分：

- 每命中一个喜好 Tag：`+1`；
- 每命中一个厌恶 Tag：`-1`；
- 料理点单与酒水点单分别判断是否满足。

需要预测标准五档评价时使用：

1. `ExGood`：总分 `>= 4`，且料理、酒水点单都满足；
2. `Good`：总分 `>= 3`，且至少满足一项点单；
3. `Normal`：总分 `>= 2`，且至少满足一项点单；
4. `Bad`：总分 `>= 1`，但未达到以上条件；
5. `Exbad`：总分 `<= 0`。

该模型不是所有挑战的通用原生规则。怪诞料理大赛、幽幽子挑战和血池地狱必须使用各自已验证的模式，不能回退到标准模型猜测。

## 料理 Tag 生成

有效 Tag 的输入顺序为：

1. 配方自带正面 Tag；
2. 额外材料 Tag；
3. 动态价格/份量 Tag；
4. 压制结果；
5. 当前流行与明星店派生 Tag。

当前已验证的动态规则：

- 价格 `< 20` 生成“实惠”；
- 价格 `> 60` 生成“昂贵”；
- 带“不可加价”的配方不生成上述两个价格 Tag；
- 基础配方材料份数与额外加料数合计 `>= 5` 生成“大份”；
- 流行喜爱/厌恶只在基础、加料、动态 Tag 及压制完成后派生；
- 明星店开启且流行喜爱为“招牌”时，只启用明星店效果，不重复占用普通流行料理 Tag。

基础配方材料是数量敏感序列。同一材料重复出现表示需要多份，也会分别占用五格材料上限，不能去重。

## Tag 压制

当前使用的压制关系：

- 肉 压制 素；
- 重油 压制 清淡；
- 饱腹 压制 下酒；
- 大份 压制 小巧；
- 灼热 压制 凉爽。

被压制的 Tag 保留在 `suppressedTags` 中供解释，但不参与后续喜好、厌恶或流行判定。界面使用语义样式和删除线表达，不在机制层写死色值。

配方负面 Tag 表示额外材料禁忌。候选组合前直接排除会命中这些负面 Tag 的材料。

## Tag 身份与映射

- 数字 Tag 映射以游戏 Addressables 资源或运行时 `DataBaseLanguage` 为权威，不能依据显示顺序或社区表推测。
- Signed Tag ID（包括 `0`、`-1` 等）只要原生字段读取成功就保持原值；是否属于合法内容 ID 由具体业务域决定，不能全局过滤负数。
- 原始映射和项目内 canonical 中文名称之间的别名归一化只在解析层进行，不修改原始身份。
- 当前运行时目录不投影未经完整验证的复杂 `TagRules` 容器；已确认的压制关系由项目规则明确维护。

重新提取映射的步骤见 [Addressables 标签映射提取手册](addressables-tag-mapping-playbook.md)。
