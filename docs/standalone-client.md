# 独立 Windows 客户端

另一台电脑可以只运行 Windows 伴随客户端，通过可信局域网连接游戏电脑。独立客户端电脑不需要安装游戏、BepInEx 或 Mod；游戏电脑仍须运行与客户端成套的完整 Mod，并开启局域网服务。

常用入口：[首次使用](#下载与首次使用) · [旧 Flutter 导入](#从旧-flutter-私有目录导入) · [更新与备份](#更新独立客户端) · [旧 Tauri 转换](#从-v131-tauri-首次转换) · [启动失败](#目录检查与启动失败)。实际可下载版本以[项目发布页](https://github.com/blockshy/mystia-steward-companion/releases)为准。

## 下载与首次使用

下载对应 Release 的 `mystia-steward-companion-companion-windows-x64.zip`，完整解压后进入外层 `mystia-steward-companion-windows-x64/` 目录，运行 `mystia-steward-companion-portable.exe`。使用独立发布包；Mod 包内的通用 EXE 继续使用 Windows 用户私有存储，不是便携入口。

当前客户端使用 Flutter，EXE、`portable-client-v1.manifest`、全部随包 DLL 和 `data/` 资源必须一起保留，不混用不同版本文件。正式 ZIP 已携带所需的本地 VC 运行库。保留包内独立文件夹，不把载荷直接散放在桌面、下载目录或其他软件目录中；目录检查与拒绝规则见[启动失败说明](#目录检查与启动失败)。

1. 在游戏电脑启动游戏和 Mod，由游戏电脑的本机主设备开启局域网服务，选择实际网卡地址并核对 Token；完整步骤见[另一台设备连接](../mods/bepinex/README.md#另一台设备连接windows--android)。
2. 首次打开独立客户端，在“设置 → 连接与设备 → 本机数据存储”选择“作为新设备开始”，或明确导入当前 Windows 用户的旧 Flutter 资料。完成选择前不会生成身份或保存偏好。
3. 在连接设置填写游戏电脑地址、端口、Token 和本设备名称，保存并连接。这里不能填写独立客户端自己的 `127.0.0.1`；导入可用的旧连接凭据后会尝试连接原地址。
4. 已有主设备的游戏主机将新客户端登记为查看设备。需要更换主设备时，先在新设备记录上“同步主配置”，等待保存确认，再“设为主设备”。

只在可信局域网使用，不把本地 API 暴露到公网。首次作为新设备开始时，默认名称为“Windows 独立客户端”；可按需要修改，名称本身不决定设备身份或权限。

## 本机配置与设备身份

独立客户端将数据保存在实际 EXE 同级的 `client-data/`，不受快捷方式“起始位置”或命令行工作目录影响，也不在外部创建 `config/MystiaStewardCompanion`：

```text
mystia-steward-companion-windows-x64/
  mystia-steward-companion-portable.exe
  portable-client-v1.manifest
  data/
  随包 DLL 与许可文件
  client-data/
    preferences.json
    window-state-v1.txt
    client-id.dpapi
    connection-token.dpapi
```

`preferences.json` 保存本机偏好、连接地址和当前身份的共享配置确认记录，`window-state-v1.txt` 保存窗口状态。两个 `.dpapi` 文件分别保存经当前用户 Windows DPAPI 加密的身份和 Token。`client-data` 还包含初始化状态等内部文件，备份和更新须保留整个目录，不只挑选上述四文件；这些文件由客户端维护，无需手动编辑。

- 同机、同一 Windows 用户下移动完整程序和 `client-data`，可继续使用原身份。存储目录不可写或被重定向时会报错，不悄悄切换到其他目录。
- 不同的全新便携目录在完成首次选择后分别创建新身份；复制已有 `client-data` 不会产生独立身份，不要将这样的副本同时作为不同设备使用。
- 复制完整资料到另一台电脑或另一 Windows 用户，并不保证 DPAPI 能解密。无法解密时原密文保留，客户端不会清空或重新生成身份；应返回原电脑和原用户环境恢复，或恢复该环境下的完整资料备份。
- 另一台电脑首次使用应解压新的完整包，不带入旧 `client-data`，再以新设备填写连接信息。需要共享推荐、自动化等配置时，使用设备页面的同步与确认流程。

“本机数据存储”显示实际存储模式，绝对位置默认收起，可按需点击“显示存储位置”。位置仅在本机页面展示，不加入业务请求或操作记录。

Mod 内置客户端仍使用 `%LOCALAPPDATA%/mystia-steward-companion/flutter-v1/`。两类客户端按明确入口选择存储，不根据局域网地址、主设备角色或启动游戏参数推测模式。

收藏、自定义配方、设备注册表和共享配置的权威数据仍由游戏电脑保存。备份 `client-data` 只能保全本机资料，不能代替游戏存档和 [Mod 数据根](../mods/bepinex/README.md#配置与数据位置)的备份。

## 从旧 Flutter 私有目录导入

仅在便携目录首次初始化、目标为空时，可以选择“导入旧 Flutter 数据”。固定来源为当前 Windows 用户的 `%LOCALAPPDATA%/mystia-steward-companion/flutter-v1/`，导入范围如下：

| 来源文件 | 导入内容 |
| --- | --- |
| `preferences.json` | 本机偏好与连接地址；属于旧身份的共享配置确认记录在连接前移除。 |
| `window-state-v1.txt` | 窗口位置与尺寸。 |
| `connection-token.dpapi` | 当前用户环境能够解密的连接 Token。 |

不接受任意历史目录，不读取或复制旧 `client-id.dpapi`，也不向旧源写入标记或删除原文件。

导入前检查偏好 JSON、窗口数据和凭据可用性，执行时再次核对源文件；损坏、源变化或目标冲突会保留原件并报错，不覆盖后继续。便携客户端使用新身份注册，导入不继承旧主设备角色或同步确认。连接后若需接管，先同步旧主配置、等待保存确认，再设为主设备。选择“作为新设备开始”后，该目录也不再满足首次导入条件。

此入口只处理旧 Flutter 私有资料，不迁移 Tauri WebView 数据，不恢复损坏的 DPAPI 密文，也不自动清理旧目录。

## 更新独立客户端

“设置 → 更新”中的检查、下载和安装状态来自当前连接的游戏电脑，表示 **游戏电脑上的 Mod 更新**。由主设备请求下载时，下载包也保存在游戏电脑；安装必须在游戏电脑通过本机连接操作，并更新该电脑的完整 Mod 包及包内客户端。它不会替换另一台电脑、或另一个独立目录里的客户端。

独立 Windows 客户端按以下步骤更新：

1. 取得与游戏电脑配套 Release 的完整 Windows 客户端 ZIP。
2. 从托盘或客户端外观页完整退出旧客户端；关闭窗口只是隐藏到托盘。
3. 先在程序目录之外备份整个 `client-data`。备份包含设备身份和加密连接凭据，应按私人资料保管；不要同时启动使用同一身份的旧、新副本。
4. 将新 ZIP 完整解压到新的空目录，在首次启动前，将旧目录的整个 `client-data` 移入新包的 `mystia-steward-companion-windows-x64/` 根。不要把旧 EXE、DLL、`data/` 或旧标记覆盖到新包中。
5. 核对底部状态栏中的客户端版本、Mod 版本与连接状态；确认新目录可正常使用后，再按需要移除旧程序目录。若在旧程序目录自行保存过文件，先保留这些资料。

在同机同一 Windows 用户下，完整保留 `client-data` 才能沿用原偏好、连接和身份；未搬入资料时会再次显示首次使用选择，选择新设备后便会生成另一身份。新目录正常使用前保留备份，不删除唯一的数据副本。程序位置改变后，原快捷方式仍可能指向旧目录，应同时更新。

即使尚未连接，或客户端与 Mod 协议不兼容，也可以进入“设置 → 更新 → 本机客户端更新”阅读说明并打开“客户端发布页”。游戏电脑显示“Mod 已是最新版本”不能证明本机客户端已经更新；当前没有独立客户端自动下载安装系统。

## 从 v1.3.1 Tauri 首次转换

旧版独立客户端可能只有一个 EXE。首次转换须退出旧托盘客户端，改用完整 Flutter Windows ZIP；不要把新 EXE 单独复制到旧位置。游戏电脑也须按[更新 Mod](../mods/bepinex/README.md#更新-mod)完成成套升级，旧 Tauri 客户端不兼容新的在线协议。

旧 Windows WebView 数据默认位于 `%LOCALAPPDATA%/com.tyukki.mystia-steward-companion/`，与 Flutter 目录不同。新客户端不会自动读取其中的 Token、设备身份或全部偏好；仅替换程序不等于清理或迁移该浏览器数据库。独立客户端首次使用仍应重新填写游戏电脑的地址和 Token。

游戏电脑上已保存的旧主设备记录与共享配置可以继续用于接管：在新客户端先同步旧主配置，等待保存确认，再设为主设备。旧主设备离线不妨碍读取其已保存的共享配置，但不会自动把主设备角色交给新身份。若共享自动化总开关已开启，完成接管后会在连接、租约和场景条件满足时恢复执行，应先核对设置。

主题、字号等本机偏好可重新设置，或通过“历史偏好迁移”导入明确支持的 JSON 白名单字段。该导入不涵盖整个 WebView，不复用旧身份或自动化执行许可；需要保留的历史资料应自行导出或保存。不要为了升级而清空设备注册表或删除 Windows 用户数据目录。

## 目录检查与启动失败

便携入口在创建数据之前验证实际 EXE 所在目录。使用包内独立文件夹；磁盘根、桌面、下载、文档、用户根、系统公共目录以及公共临时目录本身不能作为程序根。它们下面的独立子目录仍须通过完整包检查。该检查用于确认目录边界与文件完整性，不代替发布来源验证。

| 情况 | 处理方式 |
| --- | --- |
| 标记缺失、载荷缺失或摘要/大小不符 | 重新完整解压对应 ZIP；不要混用旧 EXE、DLL、资源或标记。 |
| 程序目录出现清单外文件或目录 | 将个人资料保存在程序目录之外。`client-data` 是允许的数据目录，但其中也只接受客户端已知的数据与事务文件。 |
| 路径被链接或重解析点重定向，或目录不可写 | 使用普通、可写的独立目录；不要通过改名 EXE 或删除标记绕过检查。 |
| 初次导入失败 | 保留旧源与目标文件，按错误核对损坏、占用或变化；不要用空配置覆盖已有资料。 |
| 已有凭据无法解密 | 返回原电脑、原 Windows 用户环境或恢复该环境下的完整数据备份。另一台电脑需要新设备时，重新解压完整包并使用新的空数据目录。 |

结构准入失败时不创建 `client-data`，也不回退到 AppData。通过检查后，仅在获准的程序与数据目录内进行短暂可写性探测；正式首次数据初始化仍须用户明确选择。跨机无法解密不会清空原密文，也不会自动生成替代身份。

## Android 说明

Android 使用应用私有存储与 Keystore，不使用上述 Windows 路径。更新须覆盖安装同包名、原证书签名且版本号更高的 APK；不要通过卸载或清除应用数据更新。游戏电脑的 Mod 更新同样不会安装手机上的客户端。
